# Лекция 5. Перегрузка операторов: как тип становится полноценным

> Конспект к лекции для самостоятельного чтения. Слайды (`slides.md`) повторяют структуру, конспект подробнее объясняет «почему».

## 0. О чём эта лекция

Посмотрите на этот код:

```cpp
int a = 1, b = 2;
int c = a + b;                  // складываем
if (a < b) { /* ... */ }        // сравниваем
std::cout << c;                 // печатаем
```

Всё естественно, никто не задумывается. Теперь то же самое со своим классом из прошлой лекции:

```cpp
Vec2 v1{1, 2}, v2{3, 4};
Vec2 v3 = v1 + v2;              // CE
if (v1 < v2) { /* ... */ }      // CE
std::cout << v3;                // CE
```

Ничего не работает. Почему `int` можно складывать, а ваш тип — нет?

Темы:

- Оператор как обычная функция со специальным именем.
- Шесть ролей, которые может играть тип: значение, число, упорядоченное, счётчик, притворщик, выводимое.
- Гигиена: `[[nodiscard]]` и операторы, которые лучше не трогать.
- Сводная таблица «какой оператор под какую задачу».

К концу лекции вы должны уметь написать полноценный value-type — такой, как `std::complex` или `std::chrono::duration`, который встраивается в алгоритмы STL и обобщённый код на равных с встроенными типами.

## 1. Привилегии встроенных типов

Потому что у встроенных типов операторы **встроены в язык**. У вашего типа их нет — пока вы их не напишете. И это, в сущности, единственная разница между `int` и `Vec2`: набор доступных операций.

**Задача этой лекции — научить свой тип вести себя как встроенный.** Каждый оператор — отдельная «привилегия», которую тип зарабатывает. Пойдём по ролям, которые тип может играть:

1. **Значение** — умеет корректно копироваться и присваиваться
2. **Число** — умеет арифметику
3. **Упорядоченное** — умеет сравниваться
4. **Счётчик** — умеет `++`
5. **Притворщик** — выглядит как функция, контейнер или указатель
6. **Выводимое** — умеет печататься в поток

Роли независимы: тип берёт те, которые ему по смыслу нужны, и не берёт остальные. Матрица из двух строк не должна уметь `++`, а счётчик — печататься как указатель.

## 2. Оператор — это просто функция

Прежде чем разбирать роли, снимем налёт магии. Перегруженный оператор — это **обычная функция** со специальным именем:

```cpp
Vec2 v3 = v1 + v2;
// компилятор ищет:
Vec2 v3 = operator+(v1, v2);       // свободная функция
// или:
Vec2 v3 = v1.operator+(v2);        // метод
```

Из этого следует всё остальное: у оператора есть параметры и возвращаемый тип, он может быть методом или свободной функцией, он участвует в разрешении перегрузки по обычным правилам (лекция 3).

### Какие операторы можно перегружать

В C++ можно перегружать **почти все** операторы:

```
+  -  *  /  %  =  ==  !=  <  >  <=  >=  <=>
+= -= *= /= %=  &  |  ^  ~  <<  >>  &&  ||
!  ++  --  ->  .*  ->*  ()  []  ,  new  delete
```

Нельзя перегружать:

```
::   .   .*   ?:   sizeof   typeid   alignof
```

И **нельзя** ввести новые операторы — например, нет способа сделать `**` для возведения в степень или `<<<` для какой-то своей нотации.

### Член класса vs свободная функция

Большинство операторов можно реализовать либо как метод класса, либо как свободную функцию:

```cpp
class Vec2 {
public:
    Vec2 operator+(const Vec2& other) const;     // как метод
};

Vec2 operator+(const Vec2& a, const Vec2& b);    // как свободная функция
```

Несколько исключений:

- **Только методом** могут быть: `operator=`, `operator[]`, `operator()`, `operator->`. Они привязаны к конкретному объекту.
- **Только свободной функцией** обычно делают `operator<<` и `operator>>` для потоков — потому что слева в выражении стоит `std::ostream`, а не наш объект.

Для **бинарных** операторов (`+`, `==`, `<`) свободная функция **предпочтительнее**. Метод требует, чтобы объект класса стоял **слева** от оператора: `vec + 5` — ок, `5 + vec` — CE. Свободная функция симметрична.

## 3. Роль 1: тип как значение

`operator=` — особый. Его сигнатура канонична: возвращает `T&` (чтобы можно было цепочку `a = b = c`), принимает `const T&`:

```cpp
class Buffer {
    size_t size_ = 0;
    int* data_ = nullptr;
public:
    Buffer& operator=(const Buffer& other) {
        if (this == &other) return *this;
        delete[] data_;
        size_ = other.size_;
        data_ = new int[size_];
        std::copy(other.data_, other.data_ + size_, data_);
        return *this;
    }
};
```

### Зачем self-assignment check

Если убрать `if (this == &other)` и вызвать `a = a;`:

1. `delete[] data_;` — удалили нашу память (а это та же, что и `other.data_`!)
2. `data_ = new int[size_];` — выделили новую
3. `std::copy(other.data_, other.data_ + size_, data_);` — читаем из `other.data_`, которая уже удалена

Получаем **use-after-free**. Защита — одна строка.

Самопроверка через `this == &other` сравнивает **адреса**, а не значения. Если `a` и `b` — разные объекты с одинаковым содержимым, проверка `this == &other` вернёт `false` и мы пойдём по обычному пути копирования.

### Идиома copy-and-swap

Альтернативный способ написать `operator=`, который **автоматически** решает self-assignment и заодно даёт **strong exception guarantee**:

```cpp
class Buffer {
public:
    Buffer& operator=(Buffer other) {        // принимаем по значению
        swap(*this, other);                   // меняем содержимое
        return *this;                          // other уничтожается с нашим старым ресурсом
    }

    friend void swap(Buffer& a, Buffer& b) noexcept {
        std::swap(a.size_, b.size_);
        std::swap(a.data_, b.data_);
    }
};
```

Как это работает:

- При вызове `a = b;` параметр `other` — это **копия** `b`, созданная конструктором копирования.
- Если копия не получилась (например, `new` бросил bad_alloc) — `*this` не пострадал.
- Если получилась — атомарным `swap` меняем содержимое. `swap` — noexcept, не может бросить.
- На выходе `other` (бывшее содержимое `*this`) уничтожается обычным деструктором.

При `a = a;` параметр `other` — это всё равно копия `a`. Self-assignment превращается в копию-и-swap, ничего не ломается.

Цена — лишняя копия по сравнению с проверкой `this == &other`. Зато exception safety и простой код.

### Правило трёх (и пяти, и нуля)

Логика: если класс **владеет ресурсом**, который освобождает деструктор — значит, копирование по умолчанию (member-wise copy) обычно неверно. Member-wise copy скопирует указатель — два объекта станут владеть одной памятью, при разрушении дважды освободят. Поэтому если вы написали свой деструктор — почти наверняка нужны и свой копирующий конструктор, и свой `operator=`.

Это и есть **правило трёх**: если нужен один из {деструктор, копирующий конструктор, `operator=`}, нужны все три.

С C++11 добавились move-операции, и правило стало **правилом пяти**: + move-конструктор и move-`operator=`. Подробно — на лекции 11.

Самое важное практически — **правило нуля**: большинство классов **не должны писать** ни одной из пяти. Если ваш класс состоит из полей вроде `std::vector`, `std::string`, `std::unique_ptr` — все эти типы уже знают, как себя правильно копировать и перемещать. Компилятор сгенерирует правильные операции автоматически.

## 4. Роль 2: тип как число

Канонический паттерн в C++ — **`+=` как метод**, `+` как свободная функция через `+=`:

```cpp
class Vec2 {
public:
    Vec2& operator+=(const Vec2& other) {
        x_ += other.x_;
        y_ += other.y_;
        return *this;
    }
    int x_ = 0, y_ = 0;
};

Vec2 operator+(Vec2 a, const Vec2& b) {
    a += b;
    return a;
}
```

Несколько важных деталей:

- `operator+=` — **метод**, возвращает `Vec2&` (для цепочек `a += b += c`).
- `operator+` — **свободная функция**. Принимает первый аргумент **по значению** (`Vec2 a`) — это копия, на которой мы применяем `+=`. Возвращаем эту копию.
- Логика сложения **не дублируется** — она в одном месте, в `+=`.

### Почему `+` свободная функция, а не метод

Главная причина — симметрия:

```cpp
Vec2 v;
v + 5;       // ok: метод или свободная функция — обе работают
5 + v;       // если operator+ — метод класса Vec2, не компилируется
```

Метод класса требует, чтобы **слева** был объект этого класса. Свободная функция симметрична — работает с обеих сторон, и для бинарных операторов это обычно нужно.

Часто свободный `operator+` объявляется как `friend` класса, чтобы иметь доступ к `private`:

```cpp
class Vec2 {
public:
    friend Vec2 operator+(Vec2 a, const Vec2& b) { a += b; return a; }
    // ...
};
```

`friend`-функция, определённая внутри класса, считается свободной (не методом) — но с доступом к `private`.

## 5. Роль 3: тип как упорядоченный

До C++20 для полного набора сравнений нужно было шесть перегрузок:

```cpp
bool operator==(const T&, const T&);
bool operator!=(const T&, const T&);
bool operator< (const T&, const T&);
bool operator> (const T&, const T&);
bool operator<=(const T&, const T&);
bool operator>=(const T&, const T&);
```

Это много однообразного кода. И их легко рассогласовать — например, забыть, что `a < b` и `b > a` должны быть эквивалентны, или что `a == b` должен означать `!(a < b) && !(b < a)`.

### `operator<=>` — оператор «космический корабль»

C++20 ввёл `operator<=>` (three-way comparison). Из одной перегрузки компилятор сам выводит все шесть:

```cpp
class Vec2 {
public:
    auto operator<=>(const Vec2&) const = default;
    bool operator==(const Vec2&) const = default;
    int x_, y_;
};

Vec2 a{1, 2}, b{1, 3};
a < b;     // true (лексикографически)
a == b;    // false
```

`= default` означает «сгенерируй лексикографически по полям, в порядке объявления». Этого достаточно для **большинства** классов.

Маленький нюанс — почему `==` нужен отдельно: компилятор умеет генерировать его более эффективно (через побитовое сравнение полей фиксированной длины, без полной трёхсторонней процедуры). Поэтому `==` оставлен отдельной перегрузкой, и его тоже помечают `= default`.

### Когда нужен свой `<=>`

Если стандартное сравнение «по полям» не подходит:

```cpp
class CaseInsensitive {
public:
    auto operator<=>(const CaseInsensitive& other) const {
        return to_lower(s_) <=> to_lower(other.s_);
    }
    bool operator==(const CaseInsensitive& other) const {
        return to_lower(s_) == to_lower(other.s_);
    }
private:
    std::string s_;
};
```

Возвращаемый тип `<=>` — один из трёх ordering-типов из `<compare>`:

- `std::strong_ordering` — порядок строгий, `==` означает «полностью равны». Для большинства типов.
- `std::weak_ordering` — порядок есть, но `==` означает «эквивалентны» (например, регистронезависимое сравнение строк).
- `std::partial_ordering` — порядок может быть не определён для некоторых пар. Классический пример — `float` с `NaN`: `NaN <=> 1.0` не имеет смысла.

Для большинства пользовательских типов вы будете возвращать `strong_ordering` или вообще писать `= default` и не думать об этом.

## 6. Роль 4: тип как счётчик

Префиксный и постфиксный — это **разные** операторы:

```cpp
class Counter {
    int value_ = 0;
public:
    Counter& operator++()    { ++value_; return *this; }              // ++c
    Counter  operator++(int) { Counter old = *this; ++value_; return old; }  // c++
};
```

Различаются по сигнатуре:

- **Префиксный** `operator++()` — без параметров, возвращает `T&` (на себя)
- **Постфиксный** `operator++(int)` — с фиктивным `int`-параметром (его значение никогда не используется, он нужен только чтобы перегрузки различались). Возвращает `T` (копию старого значения)

Постфиксный обязан сохранить и вернуть **копию старого значения**:

```cpp
int a = 5;
int b = a++;        // b = 5, a = 6
```

Поэтому он медленнее префиксного — для сложных типов копия может быть дорогой.

**Привычка профессионального C++:** всегда писать `++i`, кроме случаев, когда явно нужно возвращаемое значение. Это особенно важно для итераторов, где `it++` обязан скопировать итератор.

Стандартный паттерн реализации — постфиксный через префиксный:

```cpp
Counter operator++(int) {
    Counter tmp = *this;
    ++(*this);              // используем префиксный
    return tmp;
}
```

Так логика не дублируется. Аналогично для `--`.

## 7. Роль 5: тип-притворщик

Притворяться тип может тремя способами, и все три — про то, чтобы читатель кода узнал знакомый синтаксис: вызов, индексирование, разыменование.

### Притворяется функцией: `operator()`

Класс с перегруженным `operator()` ведёт себя как функция:

```cpp
class Adder {
public:
    Adder(int n) : n_(n) {}
    int operator()(int x) const { return x + n_; }
private:
    int n_;
};

Adder add5(5);
int r = add5(10);        // 15 — синтаксис вызова функции
```

Такой объект называется **функтор** (function object). Главное преимущество перед обычной функцией — **состояние**: каждый функтор может хранить свои данные. `Adder(3)` и `Adder(100)` — это два функтора с разным состоянием, но одинаковым типом.

### Функторы vs лямбды

Лямбды — это синтаксический сахар над функторами. Компилятор разворачивает:

```cpp
auto add5 = [n = 5](int x) { return x + n; };
```

— в анонимный класс с `operator()(int) const`. Захватываемые переменные становятся полями, тело лямбды — телом `operator()`.

В современном коде функторы пишут редко — лямбды короче. Но **обобщённый код STL** (`std::sort`, `std::transform`, `std::find_if`) принимает «любой вызываемый объект» — функтор, лямбду, указатель на функцию, `std::function`. Этот механизм мы подробно разберём на лекции 10 — там же появится `std::function` как обобщённый контейнер для любого callable.

### Притворяется контейнером: `operator[]`

```cpp
class Vector {
public:
    int& operator[](size_t i)             { return data_[i]; }
    const int& operator[](size_t i) const { return data_[i]; }
private:
    int* data_;
};

Vector v;
v[0] = 10;             // вызвалась не-const версия (возвращает T&)
const Vector& cv = v;
int x = cv[0];         // вызвалась const версия (возвращает const T&)
```

Несколько важных деталей.

**Возвращаемое значение — ссылка.** Возврат по значению превратил бы `v[0] = 10` в присваивание временной копии — бесполезно. Ссылка даёт **lvalue**, которому можно присвоить.

**Парные const / non-const версии.** Без `const`-версии не получится `cv[0]` для `const Vector&`. С C++23 (deducing this) эту пару можно записать одной функцией — но это уже элективная тема.

**Без проверки границ.** `operator[]` для производительности **не проверяет** индекс. Если нужна проверка — отдельный метод `at()`:

```cpp
int& at(size_t i) {
    if (i >= size_) throw std::out_of_range("...");
    return data_[i];
}
```

Это часть контракта STL: `v[i]` — быстрый и опасный, `v.at(i)` — безопасный и бросает исключение. Так устроены `std::vector`, `std::array`, `std::map`.

### Притворяется указателем: `*` и `->`

Делают объект похожим на указатель — используются в умных указателях и итераторах:

```cpp
template <typename T>
class MyUnique {
public:
    T& operator*() const  { return *ptr_; }
    T* operator->() const { return ptr_; }
private:
    T* ptr_;
};

MyUnique<Point> p(...);
p->x = 5;        // вызывается operator->
(*p).x = 5;      // эквивалент через operator*
```

Так устроены `std::unique_ptr`, `std::shared_ptr`, и **все** итераторы STL.

### Особенность `operator->`

`operator->` имеет необычную семантику. Он возвращает **указатель** (или объект с собственным `operator->`), и компилятор «доходит» через цепочку `->` до настоящего указателя — это называется **drilldown**:

```cpp
p->x;
// эквивалентно цепочке:
// p.operator->()->x;
```

Возврат `T*` означает «дальше — обычный `->` на указатель». Если бы вы возвращали из своего `operator->` ещё один объект с `operator->` — компилятор бы продолжил «прокручивать», пока не дойдёт до настоящего указателя.

Это редкая, но важная особенность — она и делает возможной перегрузку `->`.

## 8. Роль 6: тип как выводимое

`std::cout << obj` — это вызов `operator<<(std::ostream&, const Obj&)`. Слева стоит `std::ostream`, а не наш объект, поэтому мы **не можем** сделать `operator<<` методом своего класса. Только свободная функция (часто как `friend`):

```cpp
class Point {
public:
    int x_, y_;
    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        return os << "(" << p.x_ << ", " << p.y_ << ")";
    }
};

std::cout << Point{3, 4};   // (3, 4)
```

Возвращаем `os&`, чтобы можно было цепочку `cout << a << b << c`.

Для **ввода** — симметрично:

```cpp
friend std::istream& operator>>(std::istream& is, Point& p) {
    return is >> p.x_ >> p.y_;
}
```

В новом коде вывод часто делают через `std::format` / `std::print` (мы их видели на лекции 1). Для своего типа `T` форматирование настраивается через специализацию `std::formatter<T>` — это более современный механизм, чем `operator<<`. Подробнее — на семинаре или в самостоятельном чтении.

## 9. Гигиена: `[[nodiscard]]`

C++11 ввёл стандартизованный синтаксис атрибутов — `[[name]]` — для подсказок компилятору. С тех пор появилось несколько полезных, и самый частый из них — `[[nodiscard]]`. Он говорит компилятору: «если результат функции не использован — выдай предупреждение».

```cpp
[[nodiscard]] int compute() { return 42; }

compute();         // warning: ignoring return value of [[nodiscard]] function
int r = compute(); // ok
```

Полезно для:

- **Геттеров** и pure-функций — вызов без сохранения результата почти всегда баг
- **Result-типов** (`expected<T, E>`, `optional<T>`) — чтобы ошибку нельзя было незаметно пропустить
- **Resource handles** — например, `unique_ptr::release()` помечен `[[nodiscard]]`: он передаёт владение вызывающему, и потерянный результат означает утечку

Помечать `[[nodiscard]]` все геттеры в своих классах — хорошая практика. Это бесплатная защита от багов.

### Другие полезные атрибуты

- `[[likely]]` / `[[unlikely]]` (C++20) — подсказка компилятору о вероятной ветке `if`. Используются в горячем коде; обычный код их не требует.
- `[[maybe_unused]]` — снимает предупреждение об неиспользованной переменной/параметре. Полезно для параметров шаблонных функций, которые не нужны в определённой инстанциации.
- `[[deprecated("...")]]` — пометить функцию устаревшей. При вызове компилятор выдаст предупреждение.

Главная особенность атрибутов: если компилятор не знает атрибут, он его **игнорирует**. Это означает, что добавление новых атрибутов не ломает обратной совместимости.

### Чего лучше не перегружать

Технически в C++ можно перегрузить `&&`, `||`, `,`, унарный `&`. На практике — **не делайте этого**:

- **`&&` и `||`** теряют ленивые вычисления. Стандартные операторы вычисляют второй аргумент только если нужно — это часть их семантики (например, `if (p != nullptr && p->ok())`). Перегруженный `&&` всегда вычисляет оба аргумента, потому что это просто вызов функции. Это сюрприз для пользователя класса.
- **`operator,`** теряет sequence point — порядок вычислений становится непредсказуемым.
- **Унарный `operator&`** ломает `std::addressof` и многие шаблонные алгоритмы, которые ожидают получить настоящий адрес.

Перегрузка этих операторов встречается только в очень узких случаях — например, expression templates для матричных DSL. В обычном коде её нет.

## 10. Какой оператор под какую задачу

Мы начали с вопроса «почему `int` можно складывать, а свой тип нельзя» и прошли по ролям, которые тип может себе заработать. Сводка:

| Хочу, чтобы тип… | Перегружаю |
|---|---|
| корректно копировался | `operator=` (+ правило нуля, трёх и пяти) |
| поддерживал арифметику | `+=` методом, `+` свободной функцией |
| сравнивался | `<=>` и `==`, оба `= default` |
| считался | `++` префиксный, постфиксный через него |
| вызывался как функция | `operator()` |
| индексировался | `operator[]` парные + `at()` |
| работал как указатель | `operator*` и `operator->` |
| печатался | `operator<<` свободной `friend`-функцией |

Таблица читается в обе стороны: слева направо — «что написать, чтобы получить нужное поведение», справа налево — «что означает встреченный в чужом коде оператор».

## Итоги

**Главная мысль:** перегрузка операторов — не украшательство. Это способ сделать свой тип **равноправным** встроенным: он начинает встраиваться в алгоритмы STL, в обобщённый код, в привычные читателю идиомы. `std::complex`, `std::chrono::duration`, `std::string` — все они «просто классы», которые заработали полный набор ролей.

Ключевые правила:

- Оператор — обычная функция со специальным именем. Никакой магии.
- Перегружать можно почти все операторы. Нельзя: `::`, `.`, `?:`, `sizeof`, и нельзя ввести новые.
- **`operator=`:** возвращает `T&`, обязательная защита от self-assignment (или используйте copy-and-swap). **Правило нуля, трёх и пяти:** если класс не владеет ресурсом напрямую — не пишите ничего из пятёрки.
- **Арифметика:** `+=` методом, `+` свободной функцией через `+=`. Это убирает дублирование и даёт симметрию: иначе `5 + v` не скомпилируется.
- **Сравнение:** начиная с C++20 `auto operator<=>(...) const = default;` + `operator==() = default;` заменяют 6 перегрузок.
- **`++` / `--`:** реализуйте префиксный, постфиксный через него. В коде предпочитайте `++i`.
- **`operator()`** — функтор, объект-вызываемый. Лямбды — синтаксический сахар над функторами.
- **`operator[]`** — парные const / non-const версии, возвращают ссылку. Без проверки границ; для проверки — `at()`.
- **`operator*` и `operator->`** — для классов, ведущих себя как указатели (smart pointers, итераторы).
- **`operator<<`** — свободная функция, часто `friend`. Возвращает `ostream&` для цепочек.
- **`[[nodiscard]]`** — крайне полезный атрибут для геттеров и result-типов, бесплатная защита от багов.
- **Не перегружайте `&&`, `||`, `,`, унарный `&`** — это ломает ожидания пользователя.
- **Не дублируйте логику:** `+` через `+=`, `i++` через `++i`, шесть сравнений через один `<=>`.
