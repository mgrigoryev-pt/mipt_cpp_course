# 1. Привилегии встроенных типов

```cpp
int a = 1, b = 2;
int c = a + b;                  // складываем
if (a < b) { /* ... */ }        // сравниваем
std::cout << c;                 // печатаем
```

С `int` всё это работает «само». А с вашим классом?

```cpp
Vec2 v1{1, 2}, v2{3, 4};
Vec2 v3 = v1 + v2;              // CE
if (v1 < v2) { /* ... */ }      // CE
std::cout << v3;                // CE
```

---

## Почему так

У встроенных типов операторы **встроены в язык**. У вашего типа их нет — пока вы их не напишете.

Сегодняшняя задача: **научить свой тип вести себя как встроенный**. Каждый оператор — это одна отдельная «привилегия», которую тип зарабатывает.

Пойдём по ролям, которые может играть тип:

1. **Значение** — умеет копироваться и присваиваться
2. **Число** — умеет арифметику
3. **Упорядоченное** — умеет сравниваться
4. **Счётчик** — умеет `++`
5. **Притворщик** — выглядит как функция, контейнер или указатель
6. **Выводимое** — умеет печататься

<!-- header: 2. Оператор = функция -->

# 2. Оператор — это просто функция

Никакой магии: `a + b` для своего типа — это **вызов функции** со специальным именем.

```cpp
Vec2 v3 = v1 + v2;
// компилятор ищет:
Vec2 v3 = operator+(v1, v2);
```

Отсюда следует всё остальное: у оператора есть параметры, возвращаемый тип, его можно сделать методом или свободной функцией, он участвует в разрешении перегрузки.

---

## Что можно и нельзя

Перегружать можно **почти всё**:

```
+  -  *  /  %  =  ==  !=  <  >  <=  >=  <=>
+= -= *= /= %=  &  |  ^  ~  <<  >>  &&  ||
!  ++  --  ->  .*  ->*  ()  []  ,  new  delete
```

Нельзя: `::`  `.`  `?:`  `sizeof`  `typeid`  `alignof`

И нельзя придумать **новый** оператор — например, `**` для возведения в степень.

---

## Метод или свободная функция

```cpp
class Vec2 {
public:
    Vec2 operator+(const Vec2& o) const;    // метод
};

Vec2 operator+(const Vec2& a, const Vec2& b);  // свободная функция
```

- **Только методом:** `=`, `[]`, `()`, `->` — они привязаны к объекту
- **Только свободной:** `<<`, `>>` для потоков — слева стоит `ostream`, не ваш тип

Для симметричных бинарных операторов свободная функция **лучше** — почему, увидим через два слайда.

<!-- header: 3. Роль 1: значение -->

# 3. Роль 1: тип как значение

Первое, что должен уметь полноценный тип — **корректно копироваться**. Иначе он не значение, а недоразумение.

```cpp
// class Buffer { size_t size_; int* data_; ... }

Buffer& operator=(const Buffer& other) {
    if (this == &other) return *this;      // защита, см. далее
    delete[] data_;                         // освободили своё
    size_ = other.size_;
    data_ = new int[size_];                 // выделили новое
    std::copy(other.data_, other.data_ + size_, data_);
    return *this;                           // для цепочки a = b = c
}
```

Четыре шага: проверка, освобождение, выделение, копирование.

---

## Зачем self-assignment check

Без `if (this == &other)` вызов `a = a` делает так:

1. `delete[] data_` — удалили свою память
2. `std::copy(other.data_, ...)` — читаем из **той же**, уже удалённой

Результат — **use after free**. Одна строка защиты решает проблему.

Но есть способ, где эта проблема не возникает в принципе.

---

## Идиома copy-and-swap

```cpp
Buffer& operator=(Buffer other) {   // приняли ПО ЗНАЧЕНИЮ — это копия
    swap(*this, other);              // обменялись содержимым
    return *this;                    // other уносит наш старый ресурс в могилу
}

friend void swap(Buffer& a, Buffer& b) noexcept {
    std::swap(a.size_, b.size_);
    std::swap(a.data_, b.data_);
}
```

Один метод закрывает сразу три вещи: копирование, self-assignment и **strong exception guarantee** (если копия не удалась — `*this` не тронут).

---

## Правило трёх, пяти и нуля

Если классу нужен **один** из трёх — нужны все три:

1. деструктор
2. копирующий конструктор
3. `operator=` копирования

Они связаны логикой владения: если есть что освобождать, значит есть что правильно копировать.

С C++11 добавились move-операции — стало **правило пяти**, подробно на лекции 11.

**Правило нуля:** большинству классов не нужно ничего из пяти — поля вроде `vector`, `string`, `unique_ptr` всё умеют сами. Свою пятёрку пишут только те, кто владеет ресурсом напрямую.

---
<!-- header: 4. Роль 2: число -->

# 4. Роль 2: тип как число

Канонический приём: **`+=` делаем методом, `+` — свободной функцией через `+=`**.

```cpp
class Vec2 {
public:
    Vec2& operator+=(const Vec2& o) {
        x_ += o.x_; y_ += o.y_;
        return *this;
    }
    int x_ = 0, y_ = 0;
};

Vec2 operator+(Vec2 a, const Vec2& b) { a += b; return a; }
```

Логика сложения написана **один раз** — в `+=`. `+` берёт копию первого аргумента и переиспользует её.

---

## Почему `+` свободной функцией

```cpp
Vec2 v;
v + 5;       // работает и так и так
5 + v;       // если operator+ — метод Vec2, то CE!
```

Метод требует, чтобы объект стоял **слева**. Свободная функция симметрична.

Это не педантизм: `2 * matrix` должно работать так же, как `matrix * 2`. Поэтому бинарные операторы делают свободными — часто как `friend`, чтобы был доступ к `private`.

---
<!-- header: 5. Роль 3: упорядоченность -->

# 5. Роль 3: тип как упорядоченный

До C++20 полный набор сравнений — это **шесть** функций:

```cpp
bool operator==(const T&, const T&);
bool operator!=(const T&, const T&);
bool operator< (const T&, const T&);
bool operator> (const T&, const T&);
bool operator<=(const T&, const T&);
bool operator>=(const T&, const T&);
```

Много рутины — и её легко рассогласовать. Например, забыть, что `a < b` и `b > a` обязаны совпадать.

---

## `<=>` — один вместо шести

C++20 ввёл **трёхстороннее сравнение**, из которого компилятор выводит все шесть:

```cpp
class Vec2 {
public:
    auto operator<=>(const Vec2&) const = default;
    bool operator==(const Vec2&) const = default;
    int x_, y_;
};

Vec2 a{1, 2}, b{1, 3};
a < b;      // true
a >= b;     // false — тоже работает, хотя мы не писали
```

`= default` означает «сравнивай лексикографически по полям в порядке объявления».

---

## Зачем `==` отдельно

Компилятор умеет генерировать `==` **эффективнее**, чем через полное трёхстороннее сравнение — иногда побитово. Поэтому его оставили отдельной перегрузкой; её тоже помечают `= default`.

Если сравнение «по полям» не подходит — пишем сами:

```cpp
auto operator<=>(const CaseInsensitive& o) const {
    return to_lower(s_) <=> to_lower(o.s_);
}
```

Возвращаемый тип — один из трёх: `strong_ordering`, `weak_ordering`, `partial_ordering` (последний — для `float` с `NaN`).

---
<!-- header: 6. Роль 4: счётчик -->

# 6. Роль 4: тип как счётчик

Префиксный и постфиксный `++` — это **два разных оператора**:

```cpp
class Counter {
    int value_ = 0;
public:
    Counter& operator++()    { ++value_; return *this; }   // ++c
    Counter  operator++(int) { Counter old = *this; ++value_; return old; }
};
```

- Префиксный — возвращает **ссылку на себя**
- Постфиксный — принимает фиктивный `int` (только чтобы отличаться) и возвращает **копию старого значения**

Отсюда правило: **`++i` дешевле `i++`**, потому что не делает копию.

---

## Не дублируйте логику

Постфиксный реализуют **через** префиксный:

```cpp
Counter operator++(int) {
    Counter tmp = *this;
    ++(*this);            // вся логика здесь
    return tmp;
}
```

Аналогично для `--`. Особенно важно для итераторов: там `it++` копирует итератор, и в шаблонном коде это может быть дорого.

<!-- header: 7. Роль 5: притворщик -->

# 7. Роль 5: тип-притворщик

Дальше начинается интересное. Через операторы тип может **притворяться** совсем другой сущностью:

| Притворяется | Оператор |
|---|---|
| функцией | `operator()` |
| контейнером | `operator[]` |
| указателем | `operator*`, `operator->` |

На этом построена половина стандартной библиотеки: лямбды, умные указатели, итераторы.

---

## Притворяется функцией: `operator()`

```cpp
class Adder {
    int n_;
public:
    Adder(int n) : n_(n) {}
    int operator()(int x) const { return x + n_; }
};

Adder add5(5);
add5(10);         // 15 — синтаксис вызова функции!
```

Такой объект называется **функтор**. В отличие от функции, у него есть **состояние**: `Adder(3)` и `Adder(100)` — два разных «поведения» одного типа.

---

## Функтор → лямбда

Лямбды — это **синтаксический сахар** над функторами. Компилятор превращает

```cpp
auto add5 = [n = 5](int x) { return x + n; };
```

в анонимный класс, практически идентичный `Adder`.

Поэтому обобщённый код STL (`std::sort`, `std::find_if`) принимает **любой вызываемый объект** — функтор, лямбду, указатель на функцию. Всем им достаточно уметь `()`.

Функторы пишут редко — лямбды короче. Подробно — на лекции 10.

---

## Притворяется контейнером: `operator[]`

```cpp
class Vector {
    int* data_;
public:
    int&       operator[](size_t i)       { return data_[i]; }
    const int& operator[](size_t i) const { return data_[i]; }
};
```

Два важных момента:

- Возвращаем **ссылку** — иначе `v[0] = 10` присвоило бы значение временной копии
- **Парные** версии, const и не-const — иначе не поработать с `const Vector&`

---

## Контракт `[]` против `at()`

`operator[]` **не проверяет границы** — это осознанный договор в пользу скорости.

Если проверка нужна — отдельный метод:

```cpp
int& at(size_t i) {
    if (i >= size_) throw std::out_of_range("...");
    return data_[i];
}
```

Так устроены `std::vector`, `std::array`, `std::map`: `[]` быстрый и опасный, `at()` безопасный и бросает. Разделение ответственности вынесено в **имена**.

---

## Притворяется указателем: `*` и `->`

```cpp
template <typename T>
class MyUnique {
    T* ptr_;
public:
    T& operator*()  const { return *ptr_; }
    T* operator->() const { return ptr_; }
};

MyUnique<Point> p(...);
p->x = 5;          // как у настоящего указателя
(*p).x = 5;        // эквивалент
```

Так устроены **все** умные указатели и **все** итераторы STL. Тип выглядит как указатель, а внутри делает что угодно — считает ссылки, логирует, проверяет.

---

## Особенность `operator->`

`operator->` обязан вернуть **указатель** — или объект, у которого тоже есть `operator->`.

```cpp
p->x;
// разворачивается в:
p.operator->()->x;
```

Компилятор «прокручивает» цепочку `->`, пока не дойдёт до настоящего указателя. Это называется **drilldown** и именно оно позволяет перегружать `->` осмысленно.

<!-- header: 8. Роль 6: выводимое -->

# 8. Роль 6: тип как выводимое

`std::cout << obj` — это вызов `operator<<(std::ostream&, const Obj&)`.

Слева стоит **поток**, а не наш тип. Значит, методом класса это сделать нельзя — только свободной функцией. Обычно `friend`, чтобы дотянуться до `private`.

---

## Пример `operator<<`

```cpp
class Point {
public:
    int x_, y_;
    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        return os << "(" << p.x_ << ", " << p.y_ << ")";
    }
};

std::cout << Point{3, 4};   // (3, 4)
```

Возвращаем `os&` — чтобы работала цепочка `cout << a << b << c`. Симметрично для ввода — `operator>>` с `std::istream&`.

В новом коде вывод часто делают через `std::format`, специализируя `std::formatter<T>`. Подробный разбор в курс не входит.

---
<!-- header: 9. Гигиена -->

# 9. Гигиена: `[[nodiscard]]`

Атрибут говорит компилятору: «если результат выбросили — это подозрительно, предупреди».

```cpp
[[nodiscard]] int compute() { return 42; }

compute();             // warning: ignoring return value
int r = compute();     // ok
```

Где стоит ставить:

- **Геттеры** — вызов без сохранения результата бессмыслен
- **Чистые функции** — если результат не нужен, зачем звали?
- **Result-типы** (`expected`, `optional`) — чтобы ошибку нельзя было молча проигнорировать

Бесплатная защита от целого класса ошибок: помечайте все геттеры.

---

## Чего лучше **не** перегружать

Технически можно, практически — не надо:

- **`&&`, `||`** — потеряют ленивость. Стандартные вычисляют правый аргумент только при необходимости; ваш будет вычислять всегда. Это сломает ожидания пользователя.
- **`,`** — потеряет гарантию порядка вычислений.
- **унарный `&`** — сломает `std::addressof` и шаблонный код, который ждёт настоящий адрес.

Эти три встречаются только в узких DSL (expression templates для матриц). В обычном коде — никогда.

# 10. Какой оператор под какую задачу

| Хочу, чтобы тип… | Перегружаю |
|---|---|
| корректно копировался | `=` (+ правило нуля, трёх и пяти) |
| поддерживал арифметику | `+=` метод, `+` свободный |
| сравнивался | `<=>` и `==`, оба `= default` |
| считался | `++` префиксный, постфиксный через него |
| вызывался как функция | `()` |
| индексировался | `[]` парные + `at()` |
| работал как указатель | `*` и `->` |
| печатался | `<<` свободной `friend`-функцией |

# Итоги лекции

Перегрузка — не украшение, а способ сделать свой тип **равноправным** встроенному: он встраивается в алгоритмы STL и в обобщённый код.

- Оператор — обычная функция со специальным именем; `::`, `.`, `?:`, `sizeof` не перегружаются
- **`operator=`** возвращает `T&` и защищён от самоприсваивания; правило нуля, трёх и пяти
- **`+=` методом, `+` свободной функцией через него** — иначе `5 + v` не скомпилируется
- **`<=> = default`** и `== = default` заменяют шесть перегрузок сравнения
- **`++`/`--`:** реализуется префиксный, постфиксный выражается через него
- **Притворщики:** `()` — функтор, `[]` — парные const/non-const, `*`/`->` — умные указатели
- **`<<`** — свободная `friend`-функция; `&&`, `||`, `,` не трогать вовсе
- **`[[nodiscard]]`** — на всё, чей результат нельзя молча потерять
- **Не дублируйте логику:** `+` через `+=`, `i++` через `++i`, шесть сравнений через один `<=>`
