## 1.2 Кто ведёт курс

Курс читают разработчики **Endpoint Security** — систем защиты рабочих станций и серверов.
Два класса таких систем:
- **EPP** (Endpoint Protection Platform) — предотвращает: проверяет файлы и процессы, блокирует известное зло
- **EDR** (Endpoint Detection & Response) — собирает телеметрию с машины, ищет в ней подозрительные цепочки действий и даёт возможность отреагировать

Практическая часть курса будет построена на этой же тематике.

---

## Почему такой продукт пишут на C++

Агент EDR/EPP живёт на **чужой** машине и должен быть незаметным:

- **Мало ресурсов.** Пользователь работает, а не ждёт антивирус. Сборщик мусора и лишние аллокации — непозволительная роскошь
- **Постоянный поток событий.** Каждый запуск процесса, каждое обращение к файлу — событие. Их десятки тысяч в секунду
- **Работа рядом с ОС.** Системные API, драйверы, разделяемая память — всё это C и C++
- **Сбой недопустим.** Упавший агент = машина без защиты

## 1.4 Практикум: три блока и проверочная

Двенадцать заданий одного проекта, идущих вслед за лекциями:

- **три блока по три занятия**, после каждого — **проверочная пара**:
  показываете свой код и отвечаете по нему всю пару;
- **финальный блок** — ещё три занятия, ими курс и заканчивается.

На рабочем занятии часть пишем вместе на паре, остальное дописывается дома.

Проект **сквозной**: каждое занятие продолжает предыдущее, к концу курса
получается работающая программа, а не двенадцать несвязанных задач.

Отстать молча нельзя: после каждой проверочной выкладывается эталонное
решение всего блока, и следующий блок можно начинать с него.

---

## 1.5 Отчётность и экзамен

За каждую проверочную — **зачёт или незачёт**. Три блока — три зачёта,
и каждый снижает сложность экзамена:

| Зачётов | Экзамен |
|---|---|
| 3 | облегчённый |
| 2 | стандартный |
| 0–1 | полный |

Незачёт пересдаётся на консультации: один провал не закрывает дорогу.

**Автомат.** Кто сдал все три блока вместе с продвинутыми заданиями —
получает экзамен автоматом.

---

## 1.6 Как проверяется работа

Три уровня тестов:

- **свои** — написать их часть задания, на проверочной их разбирают;
- **выданные** — приходят вместе с занятием и обязаны проходить;
- **закрытые сценарии** — прогоняются при сдаче, вы их не видите.

В каждом занятии **базовая** часть (обязательна) и **продвинутая** (сверх).
Продвинутые устроены так, что их нельзя сдать не поняв: замерить и объяснить,
сравнить два дизайна, предсказать результат и проверить.

**Про `new`/`delete`.** Руками пишем ровно один раз — на занятии 1.2, чтобы
увидеть, от чего избавляет `std::unique_ptr`. Дальше только умные указатели.

---

## 1.7 Самостоятельность

Списывать и перекладывать работу на языковую модель **крайне
не рекомендуется**: курс проверяет понимание, а оно не копируется.

Запрета нет — есть проверка. На проверочной по своему коду нужно:

- рассказать, что здесь написано и зачем;
- объяснить, почему сделано так, а не иначе;
- внести правку по просьбе преподавателя, на месте.

Не объяснили или не смогли изменить — **незачёт независимо от тестов**.

Проект сквозной, и это работает само: код, написанный чужими руками
в первом блоке, отзовётся болью в третьем.

## 2.1 Кратко о C++

- Создан **Бьёрном Страуструпом** в начале 1980-х на основе C
- Компилируемый, статически типизированный, многопарадигменный
- Описан **стандартом ISO** (последние редакции: C++17, C++20, C++23)
- Сочетает **низкий уровень** (управление памятью, указатели) и **высокий уровень** (классы, шаблоны, ranges)
- Известен тем, что в нём легко выстрелить себе в ногу

---

## 2.2 Где применяется

- **Системное и embedded ПО:** ядра, драйверы, прошивки
- **Информационная безопасность:** антивирусы, EDR/EPP-агенты, сетевые анализаторы
- **Игры и графика:** Unreal Engine, движки AAA-игр
- **Высоконагруженные сервисы:** часть бэкенда Google, Яндекса, Telegram
- **HFT (high-frequency trading):** скорость критична, исключения часто запрещены
- **ML-фреймворки:** TensorFlow, PyTorch — внутри C++
- **Базы данных:** ClickHouse, RocksDB, MySQL

Общее у всех пунктов — **нужен контроль над ресурсами** машины.

---

## 2.3 Стандарты

Язык эволюционирует. Каждые 3 года выходит новый стандарт:

- **C++11/14** — move-семантика, лямбды, `auto`
- **C++17** — `optional`, `variant`, `string_view`, structured bindings
- **C++20** — концепты, ranges, `span`, `std::format`, корутины, модули
- **C++23** — `expected`, `std::print`, deducing this

**Базовый стандарт курса — C++23.** Более ранние стандарты упоминаются там, где важно, какая возможность когда появилась. Если ваш проект на старом стандарте — конкретные фичи будем по ходу подсвечивать.

# 3. Первая программа на C++

Каноничный Hello World в современном C++:

```cpp
#include <print>

int main() {
    std::print("Hello, world!\n");
}
```

Три ключевые вещи:

1. `#include <print>` — подключаем заголовочный файл
2. `int main()` — точка входа в программу
3. `std::print(...)` — функция из стандартной библиотеки

---

## 3.1 `main` как точка входа

С функции `main` начинается выполнение любой C++-программы. Минимальный валидный код:

```cpp
int main() {}
```

Возвращаемое значение `main` — это **код выхода**: `0` означает «успех», ненулевое — «ошибка». Если `return` не написан явно — компилятор сам подставит `return 0;`.

```cpp
int main() {
    return 0;   // явно сообщаем об успехе
}
```

---

## 3.2 Заголовочные файлы

```cpp
#include <print>
#include <iostream>
#include <vector>
```

`#include` — это **директива препроцессора**: подставить сюда содержимое указанного файла. Бывают:

- **Системные** — в угловых скобках: `<print>`, `<vector>`. Ищутся в стандартных путях компилятора.
- **Пользовательские** — в кавычках: `"my_header.h"`. Ищутся в директориях проекта.

В C++20 появился альтернативный механизм — **модули** (`import std;`), но они пока широко не поддерживаются.

---

## 3.3 `std::print` и `std::format`

`std::print` (C++23) — современный способ форматированного вывода:

```cpp
#include <print>
std::print("Hello, {}! You are {} years old.\n", name, age);
```

Если значений-аргументов несколько — они подставляются в `{}` по порядку.

`std::format` (C++20) делает то же самое, но **возвращает строку**:

```cpp
std::string greeting = std::format("Hello, {}!", name);
```

Тип проверяется на этапе компиляции — нельзя «забыть» аргумент или передать не тот тип.

---

## 3.4 `std::cout` — старый способ

До C++20 для вывода использовали **потоки**:

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, world!\n";
    std::cout << "Name: " << name << ", age: " << age << "\n";
}
```

Вы встретите этот стиль **повсеместно** — он остаётся валидным и широко используется. Но в новом коде предпочтительнее `std::print` / `std::format`: они короче, безопаснее и быстрее.

В этом курсе будем использовать оба, но новые примеры — на `std::print`.

---

## 3.5 Компиляция и запуск

Простейший вариант — командой:

```bash
g++ -std=c++23 hello.cpp -o hello
./hello
```

`-std=c++23` — версия стандарта, по которой компилируем. Без неё используется устаревшая по умолчанию.

В реальных проектах используются **системы сборки**: CMake, Bazel, Meson. В практикуме проект собирается пресетами CMake с первого занятия.

---

## 3.6 Переменные и ввод

Переменная в C++ объявляется с **указанием типа**:

```cpp
#include <iostream>
#include <print>

int main() {
    int age;                       // объявление
    std::cin >> age;               // чтение из стандартного ввода
    std::print("You are {}\n", age);
}
```

`int` здесь — тип переменной. Об основных типах — ниже.

Альтернатива `std::cin` для чтения — `std::scanf` (из C) и более современные API из C++23, но `std::cin` остаётся стандартным выбором.

## 4.1 Статическая vs динамическая типизация

C++ — **статически типизированный** язык. У каждой переменной есть тип, известный на этапе компиляции, и он не меняется.

```cpp
int x = 5;
x = "hello";   // CE: cannot convert const char* to int
```

В Python (динамический) тот же код работает — переменная просто связывается с новым объектом.

Плюс статики — **компилятор ловит ошибки**, минус — больше кода (приходится писать типы). В C++ есть `auto` для вывода типа, об этом — в следующих лекциях.

---

## 4.2 Основные целые типы

```cpp
int        // обычно 32 бита
long       // 32 или 64 бита (зависит от платформы!)
long long  // ≥ 64 бита
short      // ≥ 16 бит
```

Размер «обычных» типов **не фиксирован стандартом** — он зависит от платформы. Гарантируется только минимум.

У каждого есть беззнаковая версия:

```cpp
unsigned int        // 0 .. 4 294 967 295 на 32 битах
unsigned long long  // 0 .. 2^64 - 1
```

---

## 4.3 Типы с фиксированным размером

Если важна **точная** ширина — используйте типы из `<cstdint>`:

```cpp
#include <cstdint>

int8_t   i1;   // ровно 8 бит, знаковый
int16_t  i2;
int32_t  i3;
int64_t  i4;

uint8_t  u1;   // ровно 8 бит, беззнаковый
uint32_t u3;
uint64_t u4;
```

**Правило:** в новом коде по умолчанию используйте `int32_t`/`int64_t`, а не `int`/`long`. Это переносимо и предсказуемо.

---

## 4.4 `size_t`

`size_t` — беззнаковый тип, способный вместить размер любого объекта в памяти.

```cpp
std::size_t n = v.size();    // size() возвращает size_t
```

На 64-битной системе — обычно эквивалентен `uint64_t`. **Все методы STL, возвращающие размер**, возвращают `size_t`.

Подводный камень: `size_t` беззнаковый. Цикл `for (size_t i = v.size() - 1; i >= 0; --i)` — бесконечный, потому что `size_t` не может быть отрицательным.

---

## 4.5 `bool` и `char`

```cpp
bool flag = true;            // true или false
char c = 'a';                // 1 байт, символ ASCII

char8_t  c8;                 // C++20: один UTF-8 байт
char16_t c16;                // 2 байта (UTF-16)
char32_t c32;                // 4 байта (UTF-32)
wchar_t  wc;                 // «широкий» char, размер платформо-зависимый
```

`bool` формально занимает 1 байт (хотя информации в нём — 1 бит).

---

## 4.6 Числа с плавающей точкой

```cpp
float       f1 = 3.14f;      // обычно 32 бита, IEEE 754 single
double      f2 = 3.14;       // обычно 64 бита, IEEE 754 double
long double f3 = 3.14L;      // зависит от платформы
```

**По умолчанию используйте `double`.** `float` имеет меньшую точность; смысл его использовать — экономия памяти в больших массивах или работа с GPU.

Формат IEEE 754 хранит число как `знак * мантисса * 2^экспонента`. Из этого следует, что **сравнение через `==` для плавающих почти всегда некорректно** — используйте сравнение с допуском.

---

## 4.7 Арифметика и приведения

Базовые операции — как в C/Python:

```cpp
+, -, *, /, %      // арифметика
==, !=, <, >, <=, >=    // сравнение
&&, ||, !          // логические
&, |, ^, ~, <<, >> // побитовые
```

При смешивании типов компилятор делает **integer promotion**: меньшие типы повышаются до больших.

```cpp
int8_t a = 1;
int32_t b = 2;
auto c = a + b;       // c — int32_t
```

Подводный камень — **смешивание знаковых и беззнаковых**: результат становится беззнаковым. Это распространённый источник багов.

---

## 4.8 Переполнение

Что произойдёт, если `int32_t x = INT32_MAX; ++x;`?

- **Беззнаковые типы:** вычисления выполняются по модулю `2^n`. `UINT32_MAX + 1 == 0`. Это **определённое поведение**.
- **Знаковые типы:** переполнение это **UB** (undefined behaviour). Компилятор имеет право предположить, что переполнения не бывает, и оптимизировать в расчёте на это.

Практический совет: для счётчиков и индексов, где переполнение возможно — используйте `uint64_t` или явные проверки.

## 4.9 Литералы

```cpp
42        // int
42u       // unsigned int
42l       // long
42ll      // long long
42.0      // double
42.0f     // float
'a'       // char
"hello"   // const char*
true      // bool
nullptr   // null-указатель (об указателях — лекция 2)
```

Суффикс указывает тип константы — компилятору важно, какого типа литерал.

---

## 4.10 Литералы — системы счисления

Префиксы для других систем:

```cpp
0b1010    // двоичное, = 10
0x1A      // шестнадцатеричное, = 26
012       // восьмеричное, = 10
```

Внимание: **`0` в начале — это 8-чная**. `012` это **не** двенадцать, это десять. Это историческое наследие C, и оно регулярно сбивает с толку. Не используйте `0`-префикс случайно.

В C++14 появились **разделители разрядов**:

```cpp
int big = 1'000'000;       // читается легче
```

---

## 4.11 Идентификаторы

Имя переменной, функции, типа. Правила:

- Начинается с буквы или `_`
- Дальше — буквы, цифры, `_`
- **Регистр имеет значение:** `x` и `X` — разные переменные
- Нельзя совпадать с ключевыми словами (`int`, `class`, `return`...)

```cpp
int my_variable;
int MyClass;          // PascalCase для типов
int _hidden;          // подчёркивание в начале — пометка «внутреннее»

int 1bad;             // CE: нельзя начинать с цифры
int class;            // CE: занято ключевым словом
```

---

## 4.12 Беглое знакомство с `std::vector`

`std::vector` — динамический массив. Самый используемый контейнер C++:

```cpp
#include <vector>

std::vector<int> v;          // пустой вектор int'ов
v.push_back(1);              // добавить в конец
v.push_back(2);

std::print("{} {}\n", v[0], v[1]);   // 1 2
std::print("size = {}\n", v.size());  // 2
```

Углублённо вернёмся к контейнерам в лекции 13. Сейчас просто запомните: для массивов с заранее неизвестной длиной — `std::vector`, никаких `int arr[1000]`.

# 5. Выражения и управляющие конструкции

1. Объявления vs определения
2. Область видимости
3. Выражения, lvalue / rvalue
4. Ленивые вычисления
5. Префиксный vs постфиксный `++`

---

## 5.1 Объявления vs определения

Полезно различать два понятия:

- **Объявление (declaration):** «такая сущность существует и имеет такой тип». Не выделяет память, не задаёт значение.
- **Определение (definition):** «вот сама сущность». Выделяет память / задаёт реализацию.

```cpp
extern int x;          // объявление: где-то есть int x
int x = 5;             // определение: вот он

void foo();            // объявление функции (прототип)
void foo() { ... }     // определение
```

Одна сущность может быть объявлена много раз, но определена — ровно один раз (**One Definition Rule**, ODR).

---

## 5.2 Область видимости

Имя видно только в той области, где оно объявлено:

```cpp
int x = 1;        // глобальная

int main() {
    int y = 2;        // локальная для main
    {
        int z = 3;    // локальная для блока
        x = z + y;    // ok: все три видны
    }
    z = 4;            // CE: z уже не существует
}
```

В C++ ещё есть `namespace` и `class`-scope — про них в следующих лекциях.

---

## 5.3 Выражения, lvalue / rvalue

**Выражение (expression)** — то, что вычисляется и имеет значение и тип. Например, `2 + 3`, `x`, `foo()`.

Выражения делятся на категории. Грубо:

- **lvalue** — то, у чего есть «адрес». Переменная — lvalue.
- **rvalue** — временное значение. Литерал, результат арифметики, возвращённое значение функции — rvalue.

```cpp
int x = 5;
x = 10;        // ok: x — lvalue
10 = x;        // CE: 10 — rvalue, ему нельзя присвоить
```

Подробнее — в лекциях про ссылки и move-семантику.

---

## 5.4 Ленивые вычисления

Операторы `&&` и `||` вычисляют второй аргумент **только если нужно**:

```cpp
if (p != nullptr && p->ok()) { ... }
```

Если `p == nullptr`, то `p->ok()` **не вычисляется** — иначе был бы UB (разыменование nullptr).

Аналогично:

```cpp
if (cache_hit || expensive_check()) { ... }
```

Если `cache_hit` — `expensive_check()` не вызывается.

---

## 5.5 Префиксный vs постфиксный `++`

```cpp
int x = 5;
int a = ++x;       // префиксный: сначала x = 6, потом a = 6
int b = x++;       // постфиксный: сначала b = 6, потом x = 7
```

Когда возвращаемое значение не используется — оба варианта эквивалентны:

```cpp
for (int i = 0; i < n; ++i) { ... }    // эквивалентно i++
```

Для итераторов и сложных типов **префиксный быстрее**: постфиксный обязан сохранить копию старого значения. **Привычка: всегда писать `++i`**, кроме случаев, когда явно нужно возвращаемое значение.

---

## 5.6 `if` / `else` / тернарник

```cpp
if (x > 0) {
    do_something();
} else if (x == 0) {
    do_else();
} else {
    do_other();
}

int y = (x > 0) ? x : -x;     // тернарник
```

Условие может быть **любым выражением, конвертируемым в `bool`** — числа (`!= 0`), указатели (`!= nullptr`), bool-выражения.

`else if` — это просто `else` + `if`, ничего особенного.

---

## 5.7 `if` с инициализатором (C++17)

```cpp
if (auto it = m.find(key); it != m.end()) {
    use(it->second);
}
// it здесь уже не виден
```

`it` живёт **только** внутри `if/else`. Удобно, когда нужна переменная только для проверки.

Есть ещё `if constexpr` (C++17) — выбор ветки **на этапе компиляции**. Он имеет смысл только внутри шаблонов, поэтому здесь только назван; разбор — в лекции 9.

---

## 5.8 Циклы

```cpp
for (int i = 0; i < n; ++i) { /* классический */ }

while (cond) { /* пока истинно */ }

do {
    /* хотя бы один раз */
} while (cond);

for (const auto& x : container) { /* range-based, C++11 */ }
```

`break` — прервать цикл целиком, `continue` — перейти к следующей итерации.

Range-based for подробнее — в лекции про итераторы.

---

## 5.9 `switch` / `case`

```cpp
switch (n) {
    case 1:
        do_one();
        break;
    case 2:
    case 3:                              // fall-through (намеренный)
        do_two_or_three();
        break;
    default:
        do_default();
}
```

Работает только для **целочисленных** типов и `enum`. Без `break` управление **проваливается** в следующий case — частый источник багов.

---

## 5.10 `switch`: `[[fallthrough]]` (C++17)

Если fall-through намеренный — пометьте явно:

```cpp
switch (n) {
    case 1:
        do_one();
        [[fallthrough]];     // явно: «знаю, провалится в case 2»
    case 2:
        do_two();
        break;
}
```

Без атрибута компилятор может выдать предупреждение `-Wimplicit-fallthrough`. Это **современная защита от классической ошибки** «забыл `break;`».

# 6. `namespace`, `using`, препроцессор

1. `namespace` — что такое `std::`
2. `using` — алиасы и импорт имён
3. Препроцессор: `#include`, header guards

---

## 6.1 `namespace`

`namespace` — **пространство имён**, чтобы имена не конфликтовали:

```cpp
namespace math {
    double pi = 3.14;
    double sqrt(double x) { /*...*/ }
}

double r = math::sqrt(math::pi);
```

`std::cout`, `std::vector` и т. д. — это имена из пространства `std` (стандартная библиотека).

Анонимный namespace — для имён, видимых только в текущем файле:

```cpp
namespace { int hidden = 0; }   // internal linkage, видно только здесь
```

---

## 6.2 `using namespace` и `using`

```cpp
using namespace std;     // импорт ВСЕХ имён из std — обычно плохая идея
cout << "hello\n";       // теперь без std::

using std::cout;         // импорт ОДНОГО имени — лучше
cout << "hello\n";
```

`using namespace std;` в заголовочных файлах — **запрещено**: импортирует имена в каждый файл, который этот заголовок включает.

В `.cpp` локально или внутри функции — приемлемо. В крупных проектах обычно вообще не пишут.

---

## 6.3 `using` для алиасов типов

```cpp
using Score = int;                              // алиас для int
using StringMap = std::map<std::string, int>;   // короче длинного типа

StringMap scores;
```

`using` для алиасов — современная замена устаревшему `typedef`:

```cpp
typedef int Score;                              // C-style, устарело
typedef std::map<std::string, int> StringMap;
```

**В новом коде только `using`.** Он понятнее (читается слева направо) и работает с шаблонами (шаблонные алиасы — лекция 8).

---

## 6.4 Препроцессор и `#include`

`#include` — это **директива препроцессора**: подставляет содержимое файла:

```cpp
#include <iostream>      // системный заголовок (угловые скобки)
#include "myheader.h"    // пользовательский (кавычки)
```

Препроцессор работает **до** компилятора — просто текстовая подстановка. Другие директивы (`#define`, `#ifdef`, `#if`) — legacy C-механизм, в современном C++ используются редко, кроме `#include` и header guards.

---

## 6.5 Header guards

Без защиты заголовок, включённый дважды, даст **ошибку повторного определения**:

```cpp
// способ 1 — header guards (работает везде, стандарт)
#ifndef MYHEADER_H
#define MYHEADER_H
class Widget { /* ... */ };
#endif

// способ 2 — #pragma once (короче, поддерживается всеми компиляторами)
#pragma once
class Widget { /* ... */ };
```

**`#pragma once`** короче и удобнее — используйте его в новом коде.

# 7. Виды ошибок: CE / RE / UB

В C++ ошибки можно разделить на три категории:

1. **CE — Compilation Error.** Программа не скомпилировалась.
2. **RE — Runtime Error.** Программа скомпилировалась, но при выполнении что-то пошло не так.
3. **UB — Undefined Behaviour.** Программа делает то, что в стандарте не определено.

Третий пункт — самая коварная категория.

---

## 7.1 CE — Compilation Error

Компилятор отказался превратить ваш код в исполняемый файл. Например:

```cpp
int x = "hello";       // CE: cannot convert const char* to int
int main() {
    foo();             // CE: 'foo' was not declared
}
```

**Хорошие новости:** CE — это лучший вид ошибки. Компилятор подсветил место и описал проблему. Чем больше ошибок ловится на этапе компиляции, тем меньше их будет в рантайме.

---

## 7.2 RE — Runtime Error

Программа собралась, но в процессе работы упала или повела себя плохо. Примеры:

- Деление на ноль
- Обращение к несуществующему файлу
- Превышение размера контейнера: `v.at(100)` выкинет исключение `out_of_range`

В отличие от CE, RE проявляются только при выполнении и часто только при определённых входных данных. Отсюда важность тестирования.

---

## 7.3 UB — Undefined Behaviour

**Самая опасная категория.** Программа может:

- работать корректно
- упасть с segfault
- молча испортить данные
- **зависеть от уровня оптимизации компилятора**

Стандарт говорит: «в этой ситуации поведение не определено» — и компилятор имеет право делать что угодно.

```cpp
int x;            // не инициализировано
std::print("{}\n", x);   // UB: чтение из неинициализированной переменной
```

---

## 7.4 UB — практические примеры

- **Знаковое переполнение:** `INT_MAX + 1`
- **Разыменование `nullptr`:** `*p`, где `p == nullptr`
- **Выход за границы массива:** `v[v.size()]`
- **Использование объекта после уничтожения:** возврат ссылки на локальную переменную
- **Гонка данных** в многопоточном коде

**Правило выживания:** если что-то «работает, но я не уверен почему» — есть шанс, что это UB, и оно сломается на другом компиляторе или с другими флагами.

Помогают инструменты: **AddressSanitizer**, **UndefinedBehaviorSanitizer**. В практикуме они требуются к сдаче с занятия 1.2.
