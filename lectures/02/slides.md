# 1. Виды памяти

В C++ объекты живут в одной из трёх областей памяти:

1. **Стек** — для локальных переменных функций
2. **Статическая** — для глобальных и `static`-переменных
3. **Динамическая (куча)** — для объектов, временем жизни которых управляет программист

У каждой области свои **правила времени жизни** и свои подводные камни.

---

## 1.1 Стек

Локальные переменные функций живут на стеке:

```cpp
void f() {
    int x = 5;        // x на стеке
    double y = 3.14;  // y тоже
}                     // в конце функции — x и y разрушаются
```

- Выделение и освобождение — **очень быстрые** (просто сдвиг указателя стека)
- Размер ограничен (обычно 1–8 МБ на поток)
- Время жизни **жёстко привязано** к области видимости
- Слишком глубокая рекурсия → **stack overflow**

---

## 1.2 Статическая память

Глобальные переменные и `static`-переменные:

```cpp
int counter = 0;                   // глобальная — статическая память

void f() {
    static int call_count = 0;     // живёт между вызовами f
    ++call_count;
}
```

- Создаются **до** входа в `main`, разрушаются **после** выхода
- Размер фиксирован на этапе компиляции
- `static` внутри функции — **сохраняет значение между вызовами**

---

## 1.3 Динамическая память (куча)

Управляется программистом через `new` / `delete` или умные указатели:

```cpp
int* p = new int(42);   // выделили память, p указывает на неё
// ... используем p
delete p;               // освободили
```

- Время жизни **не привязано** к области видимости
- Можно вернуть указатель из функции — объект переживёт return
- **Медленнее** стека (системный вызов аллокатора)
- Если забыть `delete` — **утечка**

---

## 1.4 Сравнение

| Область | Скорость | Время жизни | Размер |
|---|---|---|---|
| Стек | очень быстро | scope | ограничен |
| Статическая | быстро | вся программа | фиксирован |
| Куча | медленнее | управляется вручную | большой |

**Правило большого пальца:** используйте стек, когда можно. Куча — только когда нужно: большие объекты, динамический размер, объекты, переживающие функцию.

# 2. Указатели

**Указатель** — переменная, хранящая адрес другого объекта в памяти.

```cpp
int x = 42;
int* p = &x;      // p хранит адрес x
```

- `int*` — тип «указатель на `int`»
- `&x` — операция «взять адрес» (если `x` — lvalue)

Указатели — основа работы с памятью в C/C++ и базовый строительный блок для всех остальных абстракций (контейнеры, умные указатели, итераторы).

---

## 2.1 Разыменование

`*p` — операция, обратная `&`: «значение по адресу `p`».

```cpp
int x = 42;
int* p = &x;
std::print("{}\n", *p);   // 42

*p = 100;                 // меняем x через указатель
std::print("{}\n", x);    // 100
```

Если `p` — указатель на тип `T`, то `*p` — выражение типа `T&` (ссылка на `T`). Со ссылками подробнее в следующей лекции.

---

## 2.2 `nullptr`

Указатель может не указывать ни на что — тогда его значение `nullptr`:

```cpp
int* p = nullptr;

if (p == nullptr) {
    std::print("пусто\n");
}

if (p) {                  // эквивалентно p != nullptr
    *p = 5;
}
```

**Разыменовать `nullptr` — это UB.** Перед `*p` всегда убеждайтесь, что указатель валиден.

До C++11 для этого использовали `NULL` (макрос) или просто `0`. **В новом коде только `nullptr`** — он типобезопасный.

---

## 2.3 Адресная арифметика

К указателю можно прибавлять и вычитать целые числа:

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;        // указатель на arr[0]

std::print("{}\n", *(p + 1));   // 20
std::print("{}\n", *(p + 2));   // 30
```

Сложение **сдвигает на `n * sizeof(T)` байт**, а не на `n` байт. То есть `p + 1` для `int*` сдвинется на 4 байта.

Эта арифметика валидна **только внутри одного массива**. Выход за границы — UB.

---

## 2.4 `const` и указатели

Есть три разных вещи, и их легко путать:

```cpp
int x = 5;

const int* p1 = &x;      // указатель на const int (нельзя менять *p1)
int* const p2 = &x;      // const-указатель (нельзя переприсвоить p2)
const int* const p3 = &x;// и то и другое
```

Правило чтения «справа налево»:

- `const int* p1` — «p1 это указатель на const int»
- `int* const p2` — «p2 это const-указатель на int»

В новом коде `const int*` часто пишут как `int const*` — смысл тот же, но правило чтения становится единообразным.

---

## 2.5 `void*`

`void*` — указатель «на что угодно». Не имеет типа, на него нельзя разыменовать.

```cpp
int x = 5;
void* p = &x;            // ok: любой указатель → void*

// std::print("{}\n", *p);   // CE: cannot dereference void*

int* px = static_cast<int*>(p);   // обратно через cast
std::print("{}\n", *px);           // 5
```

`void*` — наследие C, используется в системных API (`malloc` возвращает `void*`, `memcpy` принимает `void*`). В современном C++ обходится без него — есть шаблоны и `std::any`.

# 3. `new` и `delete`

`new T(args)` — выделить память в куче под объект типа `T` и сконструировать его.

```cpp
int* p = new int(42);
std::print("{}\n", *p);   // 42
delete p;                  // освобождаем
```

`delete p` — разрушить объект (вызвать деструктор) и освободить память.

Каждому `new` должен соответствовать ровно один `delete`. Иначе:

- Забыли `delete` → **утечка памяти**
- Вызвали `delete` дважды → **double free** (UB, обычно крэш)
- Используем `p` после `delete` → **use after free** (UB)

---

## 3.1 `new[]` и `delete[]` для массивов

Для динамических массивов есть отдельные формы:

```cpp
int* arr = new int[100];   // массив из 100 int
arr[0] = 1;
arr[99] = 2;
delete[] arr;              // именно delete[] !
```

**Важно:** `new T[n]` идёт в паре с `delete[]`, а `new T` — с `delete`. Перепутать — UB.

```cpp
int* a = new int[10];
delete a;                  // UB: должен быть delete[]
```

В современном коде вы редко пишете `new[]` руками — вместо этого `std::vector` (динамический массив) или `std::array` (статический).

---

## 3.2 Утечки памяти

```cpp
void f() {
    int* p = new int(42);
    if (something_bad) {
        return;            // утечка: delete не вызвался
    }
    delete p;
}
```

Любой ранний выход из функции (`return`, исключение) **до** `delete` — утечка.

Решение — **RAII** и умные указатели (про них — в конце лекции). Они освобождают память **автоматически** при выходе из области видимости.

---

## 3.3 Double free

```cpp
int* p = new int(42);
delete p;
delete p;                  // UB: double free
```

После `delete p` указатель `p` остаётся со старым значением, но объекта по этому адресу больше нет. Повторный `delete` пытается освободить уже освобождённую память — крэш или, что хуже, тихая порча кучи.

Опасный сценарий — когда два разных указателя указывают на один объект, и оба пытаются его удалить (**двойное владение**).

---

## 3.4 Use after free

```cpp
int* p = new int(42);
delete p;
*p = 100;                  // UB: use after free
```

После `delete` объект по адресу `p` уничтожен, но `p` всё ещё хранит тот же адрес. Чтение или запись по этому адресу — UB.

Иногда «работает» — память не успели переиспользовать. Иногда падает. Иногда даёт странные баги через час работы программы. **AddressSanitizer** (`-fsanitize=address`) находит use-after-free надёжно.

# 4. Односвязный список: узлы и указатели

Цепочка узлов — простейший способ хранить растущую последовательность записей, например последние события, пришедшие с машины.

**Узел** = значение + указатель на следующий узел. Список хранит только **голову**.

```cpp
struct Node {
    int value;
    Node* next;      // nullptr у последнего узла
};
```

```
head -> [10|*] -> [20|*] -> [30|nullptr]
```

---

## 4.1 Зачем так хранить

Элементы **не лежат подряд**: каждый узел выделяется в куче отдельно, связь задаётся указателями.

Отсюда главное свойство: **вставка и удаление не двигают соседей** — достаточно переписать пару указателей.

- узлы остаются на своих адресах, уже взятые указатели на них не протухают
- у массива вставка в середину сдвигает весь хвост, а рост переселяет все элементы на новое место

За это придётся заплатить — про цену на последнем слайде раздела.

---

## 4.2 Сырая версия: `new` руками

```cpp
Node* push_back(Node* head, int value) {
    Node* node = new Node{value, nullptr};
    if (head == nullptr) {
        return node;              // список был пуст
    }
    Node* last = head;
    while (last->next != nullptr) {
        last = last->next;
    }
    last->next = node;
    return head;
}
```

Поиск хвоста линейный; в настоящей реализации хвост хранят отдельным указателем.

---

## 4.3 Обход и освобождение

```cpp
for (Node* it = head; it != nullptr; it = it->next) {
    std::print("{} ", it->value);
}

void clear(Node* head) {
    while (head != nullptr) {
        Node* next = head->next;   // сохранить ДО delete
        delete head;
        head = next;
    }
}
```

**Подвох:** читать `head->next` после `delete head` — use after free. Забыли `clear` (или вышли раньше по `return`) — утечка всей цепочки.

---

## 4.4 Цена

- **Отдельная аллокация на каждый элемент** плюс указатель в каждом узле: накладные расходы сравнимы с самими данными.
- **Обход прыгает по памяти** — узлы лежат где придётся. Массив на том же количестве элементов обходится в разы быстрее просто потому, что лежит подряд. Про локальность — на лекции 13.

В реальном коде берут `std::list` или, гораздо чаще, `std::vector`. Про стандартные контейнеры — лекция 13.

Свой список пишут ради понимания устройства и в специальных случаях: когда нужны стабильные указатели на элементы.

Владение здесь ручное. Автоматический вариант — в разделе 7.

# 5. Массивы

В C++ массивы бывают четырёх видов:

```cpp
int a[10];                       // C-style: на стеке, фикс. размер
int* b = new int[n];             // динамический, на куче
std::array<int, 10> c;           // C++: обёртка над C-style
std::vector<int> d(n);           // C++: динамический массив
```

В современном C++ **массивы C-style использовать практически не нужно**: `std::vector` и `std::array` дают всё то же самое плюс безопасность и удобный интерфейс.

---

## 5.1 Подвох C-style массивов

```cpp
void f(int arr[10]) {            // выглядит как массив из 10
    std::print("size: {}\n", sizeof(arr));  // выведет 8 (sizeof(int*))!
}
```

При передаче в функцию C-array **распадается до указателя** — теряется информация о длине. Поэтому в C ходят два аргумента `(int* arr, size_t n)`.

В C++ для этой задачи есть `std::span` (C++20):

```cpp
void f(std::span<const int> arr) { /* знает свой размер */ }
```

---

## 5.2 `std::array` и `std::vector`

```cpp
#include <array>
#include <vector>

std::array<int, 5> a = {1, 2, 3, 4, 5};   // размер известен на компиляции
std::vector<int> v = {1, 2, 3, 4, 5};      // динамический размер

std::print("{} {}\n", a.size(), v.size());
v.push_back(6);                            // динамический рост
```

**Правило:** в новом коде C-style массивов не используйте. Размер известен на этапе компиляции — `std::array`. Иначе — `std::vector`. Подробности — на лекции 13.

# 6. `sizeof`

`sizeof` — оператор, который возвращает размер типа или объекта в байтах.

```cpp
std::print("{}\n", sizeof(int));     // 4 (обычно)
std::print("{}\n", sizeof(double));  // 8

int x = 5;
std::print("{}\n", sizeof(x));       // 4

std::vector<int> v(100);
std::print("{}\n", sizeof(v));       // ~24 (sizeof самого объекта vector, не данных!)
```

Возвращаемый тип — `size_t`. Значение известно **на этапе компиляции**.

---

## 6.1 `sizeof` в шаблонах

`sizeof` особенно полезен в обобщённом коде:

```cpp
template <typename T>
void info() {
    std::print("size = {}\n", sizeof(T));
}

info<int>();        // size = 4
info<double>();     // size = 8
```

К шаблонам подробно вернёмся в лекциях 8–9.

# 7. Variadic C-style — что это, почему не пишут

В C для функций с переменным числом аргументов был механизм `va_list`:

```cpp
#include <cstdarg>

int sum(int count, ...) {
    va_list args;
    va_start(args, count);
    int total = 0;
    for (int i = 0; i < count; ++i) total += va_arg(args, int);
    va_end(args);
    return total;
}
```

**В новом C++ так не пишут.** Для переменного числа аргументов есть variadic templates (лекция 9) — типобезопасные и красивые. C-style оставлен только для совместимости с `printf` и подобных.

# 8. RAII и умные указатели

К концу этой лекции мы умеем работать с динамической памятью через `new` / `delete`. Проблема в том, что **писать это в реальном коде опасно**:

- забыть `delete` — утечка
- удалить дважды — крэш
- удалить и продолжить пользоваться — UB

Решение — переложить ответственность за освобождение **на компилятор**. Это называется **RAII**.

---

## Почему утечка — это не «мелочь»

Короткоживущей утилите утечка почти безразлична: процесс завершился, ОС всё вернула.

Но агент защиты рабочей станции запускается при загрузке и живёт **месяцами**. Пусть он теряет 100 байт на каждом обработанном событии, а событий — 20 000 в секунду:

```
100 байт × 20 000 событий/с × 3600 с ≈ 7 ГБ в час
```

Через сутки машину нельзя использовать — и виноват в этом инструмент, который её защищает.

Долгоживущий процесс **не имеет права** течь. Отсюда правило курса: ручных `delete` не пишем.

---

## 8.1 Идея RAII

**RAII = Resource Acquisition Is Initialization.**

Принцип: ресурс владеется объектом, а его деструктор автоматически вызывается при выходе из области видимости.

```cpp
{
    SomeResourceOwner r(...);   // конструктор захватил ресурс
    use(r);
} // выход из блока — деструктор r отдал ресурс обратно
```

Это работает для любых ресурсов: памяти, файловых дескрипторов, mutex'ов, сетевых соединений. В случае памяти — реализация называется **умные указатели**.

---

## 8.2 `std::unique_ptr`

`std::unique_ptr<T>` — RAII-обёртка над одиночным указателем. Главная фишка: **сам вызывает `delete` в деструкторе**.

```cpp
#include <memory>

void f() {
    auto p = std::make_unique<int>(42);
    *p = 100;
    std::print("{}\n", *p);
}   // здесь p автоматически удалит свой int — никакого delete руками
```

`std::make_unique<T>(args...)` — стандартный способ создать `unique_ptr`. Аргументы передаются в конструктор `T`.

---

## 8.3 `unique_ptr` для классов

Работает с любым типом — собственным или из библиотеки:

```cpp
struct Point {
    int x, y;
    Point(int x, int y) : x(x), y(y) {}
};

auto p = std::make_unique<Point>(3, 4);
std::print("{} {}\n", p->x, p->y);   // 3 4
```

Доступ к полям и методам — через `->`, как у обычного указателя. К значению — через `*p`.

---

## 8.4 `unique_ptr` нельзя копировать

```cpp
auto p1 = std::make_unique<int>(42);
auto p2 = p1;                      // CE: cannot copy unique_ptr
```

Слово «unique» в названии серьёзное: **только один владелец** может существовать. Если нужно передать владение — есть `std::move`:

```cpp
auto p2 = std::move(p1);           // ok: p2 владеет, p1 теперь пустой
```

Подробно про `std::move` — на лекции 11 (move-семантика). Сейчас просто запомните: `unique_ptr` нельзя копировать, можно перемещать через `std::move`.

---

## 8.5 Список на `unique_ptr`

Вернёмся к списку из раздела 4 и перепишем владение: узел владеет следующим.

```cpp
struct Node {
    int value;
    std::unique_ptr<Node> next;
};

// last — невладеющий указатель на существующий узел
void push_back(Node* last, int value) {
    while (last->next != nullptr) {
        last = last->next.get();
    }
    last->next = std::make_unique<Node>(value, nullptr);
}
```

Ни `delete`, ни `clear` больше не нужны: цепочка освобождается сама.

---

## 8.6 Подвох: деструктор рекурсивен

Освобождение цепочки — не цикл, а **рекурсия**:

```
~unique_ptr(head) -> delete узел 1 -> ~Node
    -> ~unique_ptr(next) -> delete узел 2 -> ~Node -> ...
```

Глубина рекурсии равна длине списка, каждый уровень — кадр на стеке. Десятки тысяч узлов → **stack overflow**, причём падение случается в момент уничтожения списка, а не работы с ним.

**Правило:** список обязан разбирать цепочку **явным циклом** в своём деструкторе.

---

## 8.7 Цикл в деструкторе

```cpp
struct List {
    std::unique_ptr<Node> head;

    ~List() {
        while (head != nullptr) {
            head = std::move(head->next);
        }
    }
};
```

`head->next` отдаёт владение следующим узлом голове, после чего старый узел удаляется — его поле `next` уже пусто, и рекурсия не начинается. Глубина стека постоянна.

Цена автоматического владения: узлы освобождать не нужно, но за разбор цепочки отвечает автор списка.

---

## 8.8 `std::shared_ptr`

Если **несколько мест должны владеть одним объектом** — нужен `std::shared_ptr<T>`. Он считает, сколько на него ссылок, и удаляет объект, когда последняя пропадает.

```cpp
auto a = std::make_shared<int>(42);
auto b = a;                        // ok: счётчик ссылок = 2
std::print("{} {}\n", *a, *b);

// объект удалится, когда оба (a и b) выйдут из области видимости
```

`std::make_shared<T>(args)` — предпочтительный способ создания (быстрее и безопаснее, чем `std::shared_ptr<T>(new T(args))`).

---

## 8.9 Когда какой

- **`unique_ptr`** — по умолчанию. Уникальное владение, никаких накладных расходов сверх обычного `delete`.
- **`shared_ptr`** — когда нужно реальное разделяемое владение. Стоит дороже (счётчик ссылок, атомарные операции).

**Правило большого пальца:** всегда начинайте с `unique_ptr`. Меняйте на `shared_ptr` только когда стало ясно, что владельцев действительно несколько.

---

## 8.10 Правило в этом курсе

Дальше в практических заданиях **не пишите `new` и `delete` руками**
(исключение одно — первая половина занятия 1.2, где это и есть задание).
Используйте:

- `std::make_unique<T>(args)` вместо `new T(args)`
- `std::make_shared<T>(args)` для разделяемого владения
- `std::vector` вместо `new T[n]`
- `std::array` вместо `T arr[N]`

Это убирает целые классы багов (утечки, double free, use after free) **без потери производительности** — `unique_ptr` компилируется ровно в то же, что и ручной `new`/`delete`.

Как они устроены внутри — разберём в **лекции 15**.

# Итоги лекции

- Память делится на **стек**, **статическую** область и **кучу** — у каждой свои правила времени жизни.
- **Указатель** — переменная с адресом. `&` берёт адрес, `*` разыменовывает. `nullptr` — нет значения.
- **`new` / `delete`** — выделение и освобождение в куче; подвохи: утечка, двойное освобождение, обращение после.
- **Односвязный список** — узел «значение + указатель на следующий»; цена вставки — аллокация на элемент.
- C-style массивы заменяются на `std::array` / `std::vector`; **RAII** — ресурс владеется объектом и освобождается в деструкторе.
- Если узлы владеют друг другом через `unique_ptr`, деструктор разбирает цепочку **циклом**: рекурсия сорвёт стек.
- В практикуме — умные указатели; ручные `new`/`delete` только на занятии 1.2.
