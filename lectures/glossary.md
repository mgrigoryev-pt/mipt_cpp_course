# Глоссарий курса

Литература по C++ почти вся на английском: стандарт, cppreference, сообщения компиляторов, доклады, ответы на Stack Overflow. Поэтому термин в курсе полезен ровно настолько, насколько по нему можно найти английский источник. Здесь собраны термины, которые встречаются в лекциях и дополнительных материалах, — с английским оригиналом и коротким определением.

## Как курс пишет термины

- **Одна форма на всё.** У каждого термина одно написание — то, что стоит здесь жирным. Синонимы и самодельные переводы в материалах не используются: если в лекции 6 «срезка», то и в лекции 3 «срезка», а не «slicing».
- **Английское остаётся английским**, если так термин и живёт в русской профессиональной речи или устойчивого перевода нет: UB, ODR, RAII, lvalue, move-семантика, type erasure, structured bindings. Русский перевод дан рядом как «по-русски» — он пригодится при чтении переводных книг, но в тексте курса не употребляется.
- **Русское — если перевод устоялся** и по нему находится ответ: раскрутка стека, единица трансляции, висячая ссылка. Английский оригинал тогда стоит в скобках.
- **При первом употреблении в каждом документе** термин ссылается сюда, и рядом стоит вторая форма: «[срезка](#slicing) (object slicing)» или «[UB](#ub) (undefined behavior)». На слайдах ссылок нет, но английская форма на первом слайде с термином показана.

Термины сгруппированы по темам. Искать удобнее всего поиском по странице: и по-русски, и по-английски.

## Стандарт и категории поведения

<a id="abstract-machine"></a>**Абстрактная машина** (abstract machine) — воображаемый исполнитель, через которого стандарт описывает смысл программы. Настоящий компилятор обязан воспроизвести не её шаги, а только наблюдаемое поведение.

<a id="observable-behavior"></a>**Наблюдаемое поведение** (observable behavior) — то, что видно снаружи программы: вывод, работа с файлами, обращения к `volatile`. Совпадать с абстрактной машиной обязано только оно.

<a id="as-if"></a>**Правило as-if** (as-if rule; по-русски — правило «как если бы») — разрешение компилятору делать с программой что угодно, пока наблюдаемое поведение остаётся таким, как если бы она выполнялась буквально. На нём держатся все оптимизации.

<a id="ub"></a>**UB, undefined behavior** (по-русски — неопределённое поведение) — нарушение правил языка, после которого стандарт не обещает ничего, причём для всего выполнения, а не для одной строки. Примеры: знаковое переполнение, выход за массив, обращение к уничтоженному объекту. Лекция 1, раздел 7; [Undefined behavior и его соседи](extra/undefined-behavior/notes.md).

<a id="implementation-defined"></a>**Implementation-defined behavior** (по-русски — поведение, определяемое реализацией) — результат выбирает компилятор и платформа и обязаны его задокументировать: `sizeof(long)`, знаковость `char`. Код с ним не сломан, но непереносим.

<a id="unspecified"></a>**Unspecified behavior** (по-русски — неуточнённое, или неспецифицированное, поведение) — один из нескольких допустимых вариантов, какой — не сказано и не документируется: порядок вычисления аргументов функции. Сюда же относится **valid but unspecified state** — состояние объекта после перемещения.

<a id="erroneous"></a>**Erroneous behavior** (C++26; по-русски — ошибочное поведение) — поведение, которое определено, но заведомо неверно: чтение неинициализированной локальной переменной даёт **erroneous value**, выбранное реализацией, и компилятор не вправе считать, что такого чтения не бывает.

<a id="ifndr"></a>**Ill-formed** (некорректная программа) — текст, который не является программой на C++. Обычно компилятор обязан об этом сообщить; вариант **ill-formed, no diagnostic required** (IFNDR) — не обязан, как при нарушении ODR.

<a id="unsequenced"></a>**Unsequenced** — два вычисления, между которыми стандарт не задаёт никакого порядка. Две записи в одну переменную, не упорядоченные между собой, — UB. Упорядоченность описывается отношением **sequenced before**.

<a id="indeterminate-value"></a>**Indeterminate value** (по-русски — неопределённое значение) — «значение» памяти, которую никто не инициализировал. Прочитать его — UB; в C++26 для локальных переменных вместо него erroneous value.

<a id="storage-duration"></a>**Storage duration** (по-русски — продолжительность хранения) — сколько живёт память под объект: automatic (локальные переменные), static (глобальные и `static`), thread (`thread_local`), dynamic (`new`). Не путать с временем жизни объекта: память может существовать раньше объекта и дольше него.

<a id="lifetime"></a>**Время жизни** (lifetime) — отрезок выполнения от конца инициализации объекта до начала его уничтожения. Обращение к объекту вне времени жизни — UB. Лекция 2.

<a id="constant-evaluation"></a>**Константное вычисление** (constant evaluation) — вычисление выражения при компиляции, например для инициализации `constexpr`-переменной. UB в нём запрещено: компилятор обязан его найти и остановить сборку.

<a id="ce"></a>**CE** (compilation error) — обозначение курса для ошибки, которую находит компилятор или линкер: программа не собирается. Лекция 1, раздел 7.

<a id="re"></a>**RE** (runtime error) — обозначение курса для ошибки, которая проявляется при выполнении и определена стандартом: исключение, код ошибки, отказ ОС. Лекция 1, раздел 7.

## Сборка и связывание

<a id="translation-unit"></a>**Единица трансляции** (translation unit, TU) — один `.cpp`-файл после работы препроцессора, со всеми включёнными заголовками. Компилятор видит только её и ничего не знает о соседних. [Как C++ собирает программу](extra/build-model/notes.md).

<a id="declaration-definition"></a>**Объявление и определение** (declaration, definition) — объявление сообщает имя и тип, определение создаёт саму сущность: выделяет память под переменную, даёт тело функции. Объявлений может быть сколько угодно, определение — одно. Лекция 1.

<a id="odr"></a>**ODR, One Definition Rule** (по-русски — правило одного определения) — у каждой переменной и функции во всей программе ровно одно определение, а у класса, шаблона и `inline`-функции в каждой единице трансляции определения должны совпадать. Нарушение второй половины — IFNDR. Лекции 1 и 3.

<a id="linker"></a>**Линкер** (linker) — программа, которая собирает объектные файлы в исполняемый и вписывает адреса, которых компилятор не знал. Процесс — **линковка** (linking).

<a id="linkage"></a>**Linkage** (по-русски — связывание) — видно ли имя из других единиц трансляции: **external linkage** — видно, **internal linkage** — только в своей (`static`, безымянное пространство имён). Лекция 1.

<a id="name-mangling"></a>**Name mangling** (по-русски — искажение, или декорирование, имён) — кодирование имени функции вместе с типами параметров и пространством имён в имя символа; так перегрузки получают разные символы. Обратное преобразование — **demangling**. [Библиотеки и граница ABI](extra/libraries-abi/notes.md).

<a id="include-guard"></a>**Include guard** — защита заголовка от повторного включения в одну единицу трансляции: `#ifndef`/`#define`/`#endif` или `#pragma once`. Лекция 1.

<a id="abi"></a>**ABI, application binary interface** — договорённость на уровне машинного кода: как передаются аргументы, как устроены объекты в памяти, как кодируются имена. API совместим по исходному тексту, ABI — по собранным файлам. [Библиотеки и граница ABI](extra/libraries-abi/notes.md).

<a id="calling-convention"></a>**Calling convention** (по-русски — соглашение о вызове) — часть ABI: в каких регистрах и в каком порядке передаются аргументы, где возвращается результат, кто снимает аргументы со стека и какие регистры функция обязана сохранить. У Windows x64 и System V x86-64 они разные; `__cdecl` и `__stdcall` — её явные пометки в коде. [Библиотеки и граница ABI](extra/libraries-abi/notes.md).

<a id="build-system"></a>**Система сборки** (build system) — программа, которая по описанию проекта решает, что и в каком порядке компилировать: Make, Ninja, MSBuild. CMake над ними — генератор описаний. [CMake](extra/cmake-basics/notes.md).

<a id="build-type"></a>**Тип сборки** (build type, configuration) — набор ключей компилятора под задачу: Debug, Release, RelWithDebInfo, MinSizeRel. [CMake](extra/cmake-basics/notes.md).

<a id="debug-build"></a>**Отладочная сборка** (debug build) — сборка без оптимизаций и с отладочной информацией; противоположность — **release**.

<a id="preset"></a>**Пресет** (preset) — записанная в `CMakePresets.json` команда конфигурации или сборки, чтобы не набирать ключи руками. [CMake](extra/cmake-basics/notes.md).

<a id="target"></a>**Цель** (target) — единица сборки в CMake: исполняемый файл или библиотека со своими свойствами. [CMake](extra/cmake-basics/notes.md).

<a id="usage-requirements"></a>**Usage requirements** — свойства цели, которые передаются тем, кто её подключает: пути к заголовкам, макросы, ключи. Управляются словами `PRIVATE`, `PUBLIC`, `INTERFACE`. [CMake](extra/cmake-basics/notes.md).

## Типы, числа и преобразования

<a id="fixed-width"></a>**Типы фиксированного размера** (fixed-width integer types) — `std::int32_t`, `std::uint64_t` и соседи из `<cstdint>`: размер задан именем, а не платформой. Лекция 1.

<a id="twos-complement"></a>**Дополнительный код** (two's complement) — представление отрицательных целых, при котором `-x` получается инверсией битов `x` плюс единица. С C++20 обязателен. [Как устроены числа](extra/numbers/notes.md).

<a id="bitwise"></a>**Побитовые операции** (bitwise operations) — `&`, `|`, `^`, `~`, `<<`, `>>`: каждый бит результата считается по соответствующим битам операндов. Не путать с логическими `&&`, `||`, `!` — те работают с истинностью целиком и правый операнд вычисляют не всегда. [Как устроены числа](extra/numbers/notes.md).

<a id="bitmask"></a>**Маска** (bitmask) — число, в котором единицами отмечены интересующие биты; ею проверяют, ставят и снимают флаги. [Как устроены числа](extra/numbers/notes.md).

<a id="shift"></a>**Сдвиг** (shift) — `<<` и `>>`: биты числа переезжают на несколько разрядов. Сдвиг на число разрядов, не меньшее ширины типа, — UB. [Как устроены числа](extra/numbers/notes.md).

<a id="floating-point"></a>**Числа с плавающей точкой** (floating-point numbers) — `float` и `double`: знак, порядок и мантисса по стандарту IEEE 754. Лекция 1; [Как устроены числа](extra/numbers/notes.md).

<a id="integral-promotion"></a>**Integral promotion** (по-русски — целочисленное продвижение) — неявное расширение типов меньше `int` (`char`, `short`, `bool`) до `int` перед арифметикой. В стандарте C тот же механизм называется integer promotions.

<a id="usual-arithmetic-conversions"></a>**Обычные арифметические преобразования** (usual arithmetic conversions) — правила, по которым два операнда разных типов приводятся к общему: `int + double` даёт `double`, `int` и `unsigned` — `unsigned`. [Как устроены числа](extra/numbers/notes.md).

<a id="implicit-conversion"></a>**Неявное преобразование** (implicit conversion) — преобразование типа, которое компилятор делает сам, без записи в коде. Явное преобразование, записанное в коде, — каст.

<a id="narrowing"></a>**Сужающее преобразование** (narrowing conversion) — преобразование, которое может потерять значение: `double` в `int`, `int64_t` в `int32_t`. Инициализация списком его запрещает. Лекция 3.

<a id="cast"></a>**Каст** (cast; по-русски также приведение типа) — явное преобразование, записанное в коде: `static_cast`, `const_cast`, `reinterpret_cast`, `dynamic_cast` и запись в стиле C. Лекция 3.

<a id="upcast-downcast"></a>**Upcast и downcast** — преобразование указателя или ссылки от производного класса к базовому (вверх по иерархии, всегда безопасно) и обратно (вниз, требует проверки). Лекции 6 и 7.

<a id="endianness"></a>**Порядок байтов** (byte order, endianness) — в каком порядке байты многобайтового числа лежат в памяти: little-endian (младший первым, x86 и ARM) или big-endian (сетевой порядок). [Как устроены числа](extra/numbers/notes.md).

<a id="strict-weak-ordering"></a>**Строгий слабый порядок** (strict weak ordering) — требование к компаратору `std::sort`, `std::map` и соседей: иррефлексивность, транзитивность и транзитивность эквивалентности. Нарушить его — UB. [Как читать справочник](extra/reading-cppreference/notes.md).

<a id="strict-aliasing"></a>**Strict aliasing** — правило, по которому к объекту можно обращаться только через его собственный тип (и немногие исключения вроде `char` и `std::byte`). Чтение `float` через `int*` — UB. Лекция 3.

<a id="type-punning"></a>**Type punning** — чтение байтов объекта одного типа как объекта другого. Законный способ — `std::bit_cast` или `std::memcpy`, незаконный — `reinterpret_cast` с разыменованием. Лекция 3.

<a id="alignment"></a>**Выравнивание** (alignment) — требование, чтобы адрес объекта был кратен числу, зависящему от типа: `alignof(int)` обычно 4. Невыровненный доступ — UB. Лекция 6.

<a id="padding"></a>**Padding** (по-русски — выравнивающие байты) — пустые байты, которые компилятор вставляет между полями и в конец структуры ради выравнивания. Лекция 6.

<a id="layout"></a>**Layout** (object layout; по-русски — размещение в памяти) — как поля объекта, его базовые подобъекты и служебные указатели лежат в памяти. Лекция 6.

<a id="ebo"></a>**EBO, empty base optimization** — пустой базовый класс не занимает места в наследнике, хотя пустой объект сам по себе весит байт. Лекция 6.

<a id="sso"></a>**SSO, small string optimization** — короткая строка хранится внутри самого объекта `std::string`, без обращения к куче. [Память процесса изнутри](extra/process-memory/notes.md).

<a id="sbo"></a>**SBO, small buffer optimization** — то же для любых обёрток: небольшой объект кладётся во встроенный буфер. Так устроен `std::function`. Лекция 10.

<a id="pod"></a>**POD, plain old data** — устаревший с C++20 термин для типа, устроенного как структура языка C. Сейчас вместо него говорят trivially copyable и standard-layout. Лекция 4.

<a id="underlying-type"></a>**Underlying type** (по-русски — базовый тип перечисления) — целый тип, которым хранится перечисление: `enum class Level : std::uint8_t`. Лекция 7.

<a id="scoped-enum"></a>**Scoped enumeration** — перечисление `enum class`: его имена живут внутри перечисления и не преобразуются в целые неявно. Лекция 7.

## Выражения и значения

<a id="value-category"></a>**Категория значения** (value category) — свойство выражения, от которого зависит, к какой ссылке его можно привязать и можно ли из него перемещать: lvalue, prvalue или xvalue. Лекция 11.

<a id="lvalue"></a>**lvalue, rvalue** — две основные категории значения. lvalue — выражение с устойчивой идентичностью, у него можно взять адрес (`x`, `*p`, `v[0]`). rvalue — временное или «отдаваемое» значение (`42`, `f()`, `std::move(x)`); оно делится на **prvalue** (чистое временное) и **xvalue** (объект, из которого можно забрать ресурсы). lvalue и xvalue вместе — **glvalue**. Лекции 1 и 11.

<a id="short-circuit"></a>**Сокращённое вычисление** (short-circuit evaluation) — `&&` и `||` не вычисляют правый операнд, если результат ясен по левому. Лекция 1.

<a id="lazy-evaluation"></a>**Ленивые вычисления** (lazy evaluation) — вычисление откладывается до момента, когда результат понадобится. Так работают views из ranges. Лекция 13.

<a id="temporary"></a>**Временный объект** (temporary object) — безымянный объект, созданный вычислением выражения; уничтожается в конце полного выражения. Лекция 3.

<a id="full-expression"></a>**Полное выражение** (full-expression) — выражение, которое не является частью другого: обычно вся инструкция до точки с запятой. Лекция 3.

<a id="lifetime-extension"></a>**Продление жизни временного объекта** (lifetime extension) — временный объект, к которому сразу привязали `const T&` или `T&&`, живёт столько же, сколько ссылка. Лекция 3.

<a id="materialization"></a>**Temporary materialization** — превращение prvalue в настоящий временный объект в памяти; с C++17 происходит только тогда, когда объект действительно нужен. Лекция 11.

<a id="ref-qualifier"></a>**Ref-qualifier** — пометка метода `&` или `&&` после списка параметров: метод вызывается только у lvalue или только у rvalue. Лекция 11.

## Функции и лямбды

<a id="overload"></a>**Перегрузка** (overloading) — несколько функций или операторов с одним именем и разными параметрами. Лекции 3 и 5.

<a id="overload-resolution"></a>**Разрешение перегрузки** (overload resolution) — выбор компилятором одной перегрузки по типам аргументов: точное совпадение лучше стандартного преобразования, стандартное — лучше пользовательского. Лекция 3.

<a id="ambiguous"></a>**Неоднозначный вызов** (ambiguous call) — несколько перегрузок подходят одинаково хорошо, и компилятор отказывается выбирать: CE. Лекция 3.

<a id="signature"></a>**Сигнатура** (signature) — то, что отличает перегрузки друг от друга: имя, типы параметров, для методов — ещё квалификаторы. Возвращаемый тип в сигнатуру обычной функции не входит. Лекция 3.

<a id="inlining"></a>**Встраивание** (inlining) — оптимизация, при которой компилятор подставляет тело функции на место вызова. Ключевое слово `inline` означает другое — разрешение определять функцию в нескольких единицах трансляции. Лекция 3.

<a id="functor"></a>**Функтор** (function object) — объект класса с `operator()`, который вызывается как функция и может хранить состояние. Лекция 5.

<a id="callable"></a>**Callable** (по-русски — вызываемый объект) — всё, что можно вызвать: функция, указатель на функцию, функтор, лямбда. Лекция 10.

<a id="closure"></a>**Замыкание** (closure) — объект, в который компилятор превращает лямбда-выражение; его безымянный класс — **тип замыкания** (closure type). Лекция 10.

<a id="capture"></a>**Захват** (capture) — переменные окружения, которые лямбда кладёт в своё замыкание: по значению или по ссылке. Лекция 10.

<a id="init-capture"></a>**Захват с инициализацией** (init-capture) — захват вида `[buf = std::move(data)]`, создающий в замыкании новую переменную. Лекция 10.

<a id="callback"></a>**Колбэк** (callback) — функция, которую передают в чужой код, чтобы тот вызвал её при событии. Лекция 10.

<a id="trampoline"></a>**Трамплин** (trampoline, thunk) — маленькая функция с сигнатурой, которую ждёт C-API, пересылающая вызов в объект C++. Лекция 10.

<a id="type-erasure"></a>**Type erasure** (по-русски — стирание типа) — приём, при котором объекты разных типов хранятся за одним интерфейсом без общего базового класса: так устроены `std::function` и `std::any`. Лекция 10.

## Классы и наследование

<a id="access-specifier"></a>**Спецификатор доступа** (access specifier) — `public`, `protected`, `private`: кто вправе обращаться к члену класса. Те же слова при наследовании задают, как доступ к членам базы меняется в наследнике. Лекции 4 и 6.

<a id="member-function"></a>**Метод** (member function; в стандарте — функция-член) — функция, объявленная внутри класса. Лекция 4.

<a id="special-member-functions"></a>**Специальные функции-члены** (special member functions) — конструктор по умолчанию, копирующий и move-конструктор, копирующее и move-присваивание, деструктор. Компилятор объявляет их неявно (implicitly-declared), если программист их не написал. Лекции 4 и 11.

<a id="default-constructor"></a>**Конструктор по умолчанию** (default constructor) — конструктор, который можно вызвать без аргументов. Лекция 4.

<a id="copy-constructor"></a>**Копирующий конструктор** (copy constructor) — конструктор из `const T&`; вместе с **копирующим присваиванием** (copy assignment) определяет, что значит копия объекта. Лекция 4.

<a id="move-constructor"></a>**Move-конструктор** (move constructor) — конструктор из `T&&`, забирающий ресурсы у источника; парный ему **move-присваивание** (move assignment). Лекция 11.

<a id="memberwise"></a>**Почленное копирование** (memberwise copy) — то, что делает неявно объявленный копирующий конструктор: копирует поля по одному. Лекция 4.

<a id="rule-of-three"></a>**Правило трёх, пяти и нуля** (rule of three, five, zero) — если класс сам пишет деструктор, копирование или перемещение, ему почти наверняка нужны и остальные; лучше всего — не писать ни одной, доверив ресурсы полям-владельцам. Лекции 4 и 11.

<a id="copy-and-swap"></a>**Copy-and-swap** — идиома присваивания: сделать копию и обменяться с ней содержимым. Даёт строгую гарантию исключений. Лекция 5.

<a id="self-assignment"></a>**Самоприсваивание** (self-assignment) — `x = x`. Оператор присваивания обязан пережить его без потери данных. Лекция 5.

<a id="deducing-this"></a>**Deducing this** (explicit object parameter) — C++23: метод получает объект явным первым параметром `this Self&& self`, и одна запись заменяет константную и неконстантную перегрузки. Лекция 4.

<a id="value-semantics"></a>**Семантика значений** (value semantics) — объект ведёт себя как число: копия независима от оригинала, сравнение сравнивает содержимое. Лекция 4.

<a id="three-way"></a>**Трёхстороннее сравнение** (three-way comparison) — оператор `<=>` («spaceship»), возвращающий сразу «меньше, равно или больше»; из него компилятор выводит остальные сравнения. Лекция 5.

<a id="comparison-category"></a>**Категория сравнения** (comparison category) — тип результата `<=>`: `std::strong_ordering`, `std::weak_ordering`, `std::partial_ordering`. Лекция 5.

<a id="aggregate"></a>**Агрегат** (aggregate) — массив или класс без пользовательских конструкторов, приватных полей и виртуальных функций; его можно заполнить списком значений — **агрегатная инициализация** (aggregate initialization). Лекция 4.

<a id="list-initialization"></a>**Инициализация списком** (list-initialization) — инициализация фигурными скобками: `int x{5}`, `Point p{1, 2}`. Запрещает сужающие преобразования. Лекции 3 и 4.

<a id="designated-initializers"></a>**Designated initializers** — C++20: агрегатная инициализация с именами полей, `Point{.x = 1, .y = 2}`. Лекция 4.

<a id="member-initializer-list"></a>**Список инициализации членов** (member initializer list) — часть конструктора после двоеточия, где инициализируются поля и базы. Не путать с `std::initializer_list`. Лекция 4.

<a id="scope"></a>**Область видимости** (scope) — часть программы, где имя доступно без квалификации: блок, функция, класс, пространство имён. Лекция 1.

<a id="namespace"></a>**Пространство имён** (namespace) — именованная область видимости для группы объявлений. Лекция 1.

<a id="unnamed-namespace"></a>**Безымянное пространство имён** (unnamed namespace) — `namespace { ... }`: всё внутри получает internal linkage и не видно из других единиц трансляции. Лекция 1.

<a id="type-alias"></a>**Псевдоним типа** (type alias) — второе имя для типа, `using Pid = std::uint32_t;`. С параметрами — **шаблон псевдонима** (alias template). Лекция 1.

<a id="base-derived"></a>**Базовый и производный класс** (base class, derived class) — класс, от которого наследуют, и наследующий. Производный класс в тексте курса называют и наследником. Лекция 6.

<a id="subobject"></a>**Подобъект** (subobject) — объект внутри другого: поле или часть базового класса. Лекция 6.

<a id="multiple-inheritance"></a>**Множественное наследование** (multiple inheritance) — наследование от нескольких базовых классов сразу. Лекция 6.

<a id="diamond"></a>**Ромбовидное наследование** (diamond inheritance) — класс наследует одну базу по двум путям и получает её дважды; отсюда «ромбовидная проблема» (diamond problem). Лекция 6.

<a id="virtual-inheritance"></a>**Виртуальное наследование** (virtual inheritance) — наследование `virtual public Base`, при котором общая база в ромбе существует в одном экземпляре. Лекция 6.

<a id="most-derived"></a>**Наиболее производный класс** (most derived class) — настоящий тип полного объекта, нижний в цепочке наследования. Он инициализирует виртуальные базы. Лекция 6.

<a id="slicing"></a>**Срезка** (object slicing) — копирование наследника в объект базового класса по значению: от наследника остаётся только базовая часть. Лекции 3 и 6.

<a id="subtyping"></a>**Подтипизация** (subtyping) — отношение, при котором объект производного класса можно использовать везде, где ожидается базовый. Лекция 6.

<a id="is-a"></a>**Is-a и has-a** — два отношения между классами: «является» (наследование) и «содержит» (поле, композиция). Лекции 4 и 6.

<a id="virtual-function"></a>**Виртуальная функция** (virtual function) — метод, вызов которого через указатель или ссылку на базу выбирается по настоящему типу объекта. Лекция 7.

<a id="pure-virtual"></a>**Чисто виртуальная функция** (pure virtual function) — виртуальная функция без реализации, `= 0`. Класс с ней — **абстрактный**. Лекция 7.

<a id="abstract-class"></a>**Абстрактный класс** (abstract class) — класс хотя бы с одной чисто виртуальной функцией; создать его объект нельзя. Лекция 7.

<a id="override"></a>**Переопределение** (overriding) — определение в наследнике виртуальной функции базы с той же сигнатурой; помечается `override`. Лекция 7.

<a id="binding"></a>**Статическое и динамическое связывание** (static binding, dynamic binding) — выбор вызываемой функции при компиляции по объявленному типу или при выполнении по настоящему. Лекция 7.

<a id="dynamic-dispatch"></a>**Динамическая диспетчеризация** (dynamic dispatch) — механизм динамического связывания: вызов через таблицу указателей на функции. Лекция 7.

<a id="vtable"></a>**vtable, vptr** (по-русски — таблица виртуальных функций и указатель на неё) — таблица адресов виртуальных функций класса и скрытое поле объекта, указывающее на неё. Стандарт их не требует, но так делают все компиляторы. Лекция 7.

<a id="devirtualization"></a>**Devirtualization** — оптимизация, при которой компилятор заменяет виртуальный вызов прямым, если знает настоящий тип объекта. Лекция 7.

<a id="rtti"></a>**RTTI, run-time type information** — информация о типах во время выполнения, на которой работают `dynamic_cast` и `typeid`. Лекция 7.

## Шаблоны

<a id="template"></a>**Шаблон** (template) — описание семейства функций, классов или переменных с параметрами-типами или значениями. Лекция 8.

<a id="instantiation"></a>**Инстанцирование** (instantiation) — порождение компилятором конкретной функции или класса из шаблона для конкретных аргументов. Лекция 8.

<a id="deduction"></a>**Вывод типов** (type deduction, template argument deduction) — определение компилятором аргументов шаблона или типа `auto` по выражению. Лекции 8, 9 и 12.

<a id="ctad"></a>**CTAD, class template argument deduction** — C++17: вывод аргументов шаблона класса из аргументов конструктора, `std::vector v{1, 2, 3}`. Лекция 8.

<a id="deduction-guide"></a>**Deduction guide** — подсказка компилятору, как выводить аргументы шаблона класса из аргументов конструктора. Лекция 8.

<a id="specialization"></a>**Специализация** (specialization) — отдельная реализация шаблона для конкретных аргументов: **полная** (explicit specialization) — для всех параметров, **частичная** (partial specialization) — для части. Лекция 8.

<a id="primary-template"></a>**Основной шаблон** (primary template) — исходное объявление шаблона, которое используется, когда ни одна специализация не подошла. Лекция 8.

<a id="non-type-parameter"></a>**Non-type template parameter** — параметр шаблона, который является значением, а не типом: `std::array<int, 4>`. В C++26 переименован в constant template parameter. Лекция 8.

<a id="structural-type"></a>**Structural type** — тип, значение которого можно передать как non-type template parameter: целые, указатели, простые структуры без приватных полей. Лекция 8.

<a id="variable-template"></a>**Шаблон переменной** (variable template) — шаблонная переменная, например `std::is_integral_v<T>`. Лекция 8.

<a id="dependent-name"></a>**Зависимое имя** (dependent name) — имя внутри шаблона, смысл которого зависит от параметра: `T::value_type`. Требует подсказок `typename` и `template`. Лекция 8.

<a id="two-phase"></a>**Двухфазный поиск имён** (two-phase name lookup) — шаблон проверяется дважды: при определении — всё, что от параметров не зависит, при инстанцировании — остальное. Лекция 8.

<a id="sfinae"></a>**SFINAE, substitution failure is not an error** — неудачная подстановка аргументов в шаблон функции не ошибка, а только исключение кандидата из разрешения перегрузки. В курс не входит; упоминается в лекции 8.

<a id="concept"></a>**Концепт** (concept) — C++20: именованное требование к параметру шаблона, например `std::integral`. Лекции 8 и 12.

<a id="type-traits"></a>**Type traits** — шаблоны из `<type_traits>`, отвечающие на вопросы о типах при компиляции: `std::is_integral_v<T>`, `std::remove_cvref_t<T>`. Лекция 8.

<a id="variadic"></a>**Variadic template** (по-русски — шаблон с переменным числом параметров) — шаблон, принимающий любое количество аргументов. Лекция 9.

<a id="parameter-pack"></a>**Пакет параметров** (parameter pack) — параметр, соответствующий нулю или более аргументов: `typename... Ts` (пакет параметров шаблона) и `Ts... args` (пакет параметров функции). Лекция 9.

<a id="pack-expansion"></a>**Раскрытие пакета** (pack expansion) — запись `pattern...`, которую компилятор разворачивает в список: по одному экземпляру образца на элемент пакета. Лекция 9.

<a id="fold"></a>**Fold expression** (по-русски — выражение свёртки) — C++17: применение бинарного оператора ко всем элементам пакета, `(args + ...)`. Бывает унарным и бинарным, левым и правым. Лекция 9.

<a id="constant-folding"></a>**Свёртка констант** (constant folding) — оптимизация, при которой компилятор вычисляет выражения из констант сам. Лекция 7.

<a id="forwarding-reference"></a>**Forwarding reference** — параметр вида `T&&`, где `T` выводится: принимает и lvalue, и rvalue. У Скотта Мейерса — universal reference. Лекции 9 и 11.

<a id="reference-collapsing"></a>**Reference collapsing** (по-русски — схлопывание ссылок) — правило, по которому ссылка на ссылку превращается в одну: `& &&` даёт `&`, `&& &&` даёт `&&`. Лекция 9.

<a id="perfect-forwarding"></a>**Идеальная передача** (perfect forwarding) — передача аргумента дальше с сохранением его категории значения через `std::forward`. Лекция 11.

<a id="decay"></a>**Распад** (decay) — неявное превращение массива в указатель на первый элемент и функции в указатель на функцию; при выводе типа по значению вдобавок отбрасываются ссылки и `const`. Лекции 2 и 9.

## Перемещение и копирование

<a id="move-semantics"></a>**Move-семантика** (move semantics) — передача ресурсов объекта другому объекту вместо копирования: из источника забирают, а не копируют. Лекция 11.

<a id="moved-from"></a>**Moved-from** — состояние объекта после перемещения из него: valid but unspecified, то есть объект можно уничтожить или присвоить ему новое значение, но полагаться на содержимое нельзя. Лекция 11.

<a id="copy-elision"></a>**Copy elision** — пропуск копирования или перемещения при создании объекта. **RVO** (return value optimization) — при возврате временного, с C++17 обязательна; **NRVO** (named return value optimization) — при возврате именованной локальной переменной, разрешена, но не обязательна. Лекция 11.

## Память и владение

<a id="stack-frame"></a>**Кадр стека** (stack frame) — участок стека под один вызов функции: её локальные переменные, адрес возврата, сохранённые регистры. Лекция 2.

<a id="stack-overflow"></a>**Переполнение стека** (stack overflow) — стек кончился, обычно из-за глубокой рекурсии или большого массива на стеке. Лекция 2.

<a id="heap"></a>**Куча** (heap, free store) — динамическая память, которую выделяют `new` и `malloc`. Лекция 2.

<a id="allocator"></a>**Аллокатор** (allocator) — код, который выделяет и освобождает память: системный под `new` и `malloc` или объект, передаваемый контейнеру. Лекция 2; [Память процесса изнутри](extra/process-memory/notes.md).

<a id="memory-leak"></a>**Утечка памяти** (memory leak) — память, которую выделили и не освободили, хотя она больше не нужна. Лекция 2.

<a id="ownership"></a>**Владение** (ownership) — ответственность за освобождение ресурса. Единственный владелец — **уникальное владение** (`std::unique_ptr`), несколько — **разделяемое** (`std::shared_ptr`); указатель без ответственности — невладеющий. Лекции 2 и 15.

<a id="raw-pointer"></a>**Сырой указатель** (raw pointer) — обычный указатель `T*`, в отличие от умного. Лекция 2.

<a id="smart-pointer"></a>**Умный указатель** (smart pointer) — класс, который владеет объектом и освобождает его в деструкторе: `std::unique_ptr`, `std::shared_ptr`. Лекции 2 и 15.

<a id="raii"></a>**RAII, resource acquisition is initialization** (по-русски — получение ресурса есть инициализация) — ресурс захватывается в конструкторе объекта и освобождается в его деструкторе, поэтому освобождается при любом выходе из области видимости. Лекция 2.

<a id="control-block"></a>**Control block** (по-русски — блок управления) — служебный объект `std::shared_ptr`: счётчики владельцев и наблюдателей и deleter. Лекция 15.

<a id="reference-count"></a>**Счётчик ссылок** (reference count) — число владельцев объекта; объект уничтожается, когда счётчик доходит до нуля. Лекции 2 и 15.

<a id="deleter"></a>**Deleter** — функция или функтор, которым умный указатель освобождает объект вместо `delete`: например, `fclose` для файла. Лекции 2 и 15.

<a id="dangling"></a>**Висячая ссылка, висячий указатель** (dangling reference, dangling pointer) — ссылка или указатель на объект, время жизни которого кончилось. Обращение через них — UB. Лекции 3 и 10.

<a id="use-after-free"></a>**Use-after-free** — обращение к памяти после её освобождения. Частный случай висячего указателя и одна из главных находок ASan. Лекция 2.

<a id="double-free"></a>**Double free** — повторное освобождение одной и той же памяти. UB. Лекция 2.

<a id="view"></a>**View** (non-owning view; по-русски — невладеющее представление) — объект, который ссылается на чужие данные и не владеет ими: `std::string_view`, `std::span`, представления из ranges. Лекции 13 и 14.

## Контейнеры и алгоритмы

<a id="stl"></a>**STL** — стандартная библиотека шаблонов: контейнеры, итераторы, алгоритмы. Лекция 13.

<a id="iterator-category"></a>**Категория итератора** (iterator category) — какие операции итератор поддерживает: input, forward, bidirectional, random access, contiguous. От неё зависит, какие алгоритмы с ним работают. Лекция 13.

<a id="half-open"></a>**Полуоткрытый диапазон** (half-open range) — пара итераторов `[begin, end)`: первый указывает на элемент, второй — за последний. Лекция 13.

<a id="iterator-invalidation"></a>**Инвалидация итераторов** (iterator invalidation) — итераторы, указатели и ссылки на элементы контейнера перестают быть действительными после изменения контейнера. Обращение через них — UB. Лекция 13.

<a id="amortized"></a>**Амортизированная сложность** (amortized complexity) — средняя стоимость операции на длинной последовательности: `push_back` иногда перевыделяет буфер, но в среднем стоит O(1). Лекция 13.

<a id="hash-table"></a>**Хеш-таблица** (hash table) — структура, раскладывающая элементы по корзинам по значению хеш-функции; так устроены `unordered_map` и `unordered_set`. Лекция 13.

<a id="bucket"></a>**Bucket** (по-русски — корзина) — ячейка хеш-таблицы, в которую попадают элементы с одинаковым остатком хеша. Лекция 13.

<a id="rehash"></a>**Rehash** — перестройка хеш-таблицы с большим числом корзин, когда элементов стало слишком много. Лекция 13.

<a id="red-black-tree"></a>**Красно-чёрное дерево** (red-black tree) — сбалансированное дерево поиска, на котором обычно устроены `std::map` и `std::set`. Лекция 13.

<a id="adl"></a>**ADL, argument-dependent lookup** — поиск имени функции в пространствах имён её аргументов; поэтому `swap(a, b)` находит `std::swap` для типов из `std`. Лекция 13.

<a id="structured-bindings"></a>**Structured bindings** (по-русски — структурное связывание) — C++17: разбор пары, кортежа или структуры на именованные переменные, `auto [key, value] = *it`. Лекция 13.

<a id="range-for"></a>**Range-based for** — цикл `for (auto& x : container)`. Лекция 1.

<a id="erase-remove"></a>**Erase-remove** — идиома удаления элементов из вектора: `std::remove_if` сдвигает оставляемые вперёд, `erase` отрезает хвост. С C++20 — `std::erase_if`. Лекция 13.

<a id="vocabulary-types"></a>**Утилитарные типы** (vocabulary types) — типы стандартной библиотеки, которыми функции обмениваются данными: `std::optional`, `std::variant`, `std::expected`, `std::string_view`, `std::span`. Лекция 14.

<a id="tagged-union"></a>**Размеченное объединение** (tagged union, sum type) — значение одного из нескольких типов вместе с пометкой, какого именно; в C++ — `std::variant`. Лекция 14.

## Ошибки и исключения

<a id="exception-safety"></a>**Exception safety** (по-русски — безопасность исключений) — что функция обещает, если бросила исключение: **basic guarantee** — утечек нет, объекты в согласованном состоянии; **strong guarantee** — всё как до вызова; **nothrow guarantee** — исключений не будет. Лекции 5, 11 и 14.

<a id="stack-unwinding"></a>**Раскрутка стека** (stack unwinding) — выход из функций по цепочке вызовов при исключении с вызовом деструкторов локальных объектов. Лекция 3; [Как устроены исключения](extra/exceptions-inside/notes.md).

<a id="landing-pad"></a>**Landing pad** (по-русски — посадочная площадка) — фрагмент функции, куда раскрутка передаёт управление, чтобы вызвать деструкторы или войти в `catch`. [Как устроены исключения](extra/exceptions-inside/notes.md).

<a id="personality-routine"></a>**Personality routine** — функция среды выполнения, которая по таблицам решает, что делать с исключением в данном кадре. [Как устроены исключения](extra/exceptions-inside/notes.md).

<a id="zero-cost"></a>**Zero-cost exceptions** — модель исключений, в которой код без броска не платит ничего, а вся стоимость переносится на бросок. [Как устроены исключения](extra/exceptions-inside/notes.md).

<a id="seh"></a>**SEH, structured exception handling** — механизм исключений Windows, поверх которого MSVC реализует исключения C++. [Как устроены исключения](extra/exceptions-inside/notes.md).

<a id="happy-path"></a>**Успешный путь** (happy path) — ветка выполнения, в которой ошибок не случилось. Лекция 14.

<a id="hot-path"></a>**Горячий путь** (hot path) — код, который выполняется чаще всего и определяет скорость программы. Лекция 14.

<a id="exit-code"></a>**Код завершения** (exit code, exit status) — число, которое процесс возвращает ОС: `return` из `main` или аргумент `exit`. Ноль — успех. Лекция 1.

<a id="access-violation"></a>**Нарушение доступа** (access violation) — обращение к памяти, которой у процесса нет или которая защищена, на Windows; на Linux то же называется **segmentation fault**. [Загрузка процесса](extra/process-loading/notes.md).

<a id="segfault"></a>**Segmentation fault** (segfault) — сигнал `SIGSEGV`, которым Linux останавливает процесс при недопустимом обращении к памяти. Лекция 2.

## Многопоточность

<a id="thread"></a>**Поток** (thread) — независимая последовательность выполнения внутри процесса. Не путать с потоком ввода-вывода (stream). Лекция 15.

<a id="data-race"></a>**Гонка данных** (data race) — два потока обращаются к одной памяти без синхронизации, и хотя бы один пишет. UB. Лекция 15.

<a id="race-condition"></a>**Состояние гонки** (race condition) — результат зависит от того, в каком порядке выполнятся потоки. Не обязательно UB: гонка бывает и при правильной синхронизации каждой операции. Лекция 15.

<a id="mutex"></a>**Мьютекс** (mutex) — объект взаимного исключения: захватить его может только один поток, остальные ждут. Лекция 15.

<a id="lock"></a>**Блокировка** (lock) — захват мьютекса; RAII-обёртки над ней — `std::lock_guard`, `std::unique_lock`, `std::scoped_lock`. Лекция 15.

<a id="critical-section"></a>**Критическая секция** (critical section) — участок кода, выполняемый под мьютексом. Лекция 15.

<a id="deadlock"></a>**Deadlock** (по-русски — взаимная блокировка) — потоки ждут друг друга по кругу, и ни один не может продолжить. Лекция 15.

<a id="condition-variable"></a>**Условная переменная** (condition variable) — объект, на котором поток засыпает до сигнала от другого потока. Лекция 15.

<a id="spurious-wakeup"></a>**Ложное пробуждение** (spurious wakeup) — поток просыпается на условной переменной без сигнала; поэтому условие всегда проверяется в цикле. Лекция 15.

<a id="atomic"></a>**Атомарная операция** (atomic operation) — операция, которую другие потоки видят либо целиком, либо никак: `std::atomic`. Лекция 15.

<a id="memory-model"></a>**Модель памяти** (memory model) — правила, по которым записи одного потока становятся видны другим. В курс не входит; упоминается в лекции 15.

<a id="lock-free"></a>**Lock-free** — алгоритм без мьютексов, в котором хотя бы один поток всегда продвигается. Лекция 15.

<a id="thread-safety"></a>**Потокобезопасность** (thread safety) — свойство кода работать правильно при одновременных вызовах из нескольких потоков. Лекция 15.

<a id="producer-consumer"></a>**Producer-consumer** (по-русски — производитель-потребитель) — схема, в которой одни потоки кладут задания в очередь, а другие забирают. Лекция 15.

<a id="thread-pool"></a>**Пул потоков** (thread pool) — набор заранее созданных рабочих потоков, которые берут задания из общей очереди. Лекция 15.

<a id="cooperative-cancellation"></a>**Кооперативная отмена** (cooperative cancellation) — поток не убивают снаружи, а просят остановиться, и он сам проверяет просьбу: `std::stop_token`. Лекция 15.

<a id="coroutine"></a>**Корутина** (coroutine; по-русски также сопрограмма) — функция, которая умеет приостанавливаться и продолжать работу. В курс не входит; упоминается в лекции 15.

## Процесс, ОС и процессор

<a id="disassembler"></a>**Дизассемблер** (disassembler) — программа, которая печатает машинный код собранного файла в виде команд процессора: `llvm-objdump -d`, `objdump -d`. [Машинный код](extra/asm-basics/notes.md).

<a id="register"></a>**Регистр** (register) — ячейка памяти внутри самого процессора, доступная за один такт; на x86-64 их шестнадцать общего назначения, и почти каждая команда работает с регистрами, а не с оперативной памятью. [Машинный код](extra/asm-basics/notes.md).

<a id="machine-instruction"></a>**Команда процессора** (instruction) — одно действие машинного кода: переслать, сложить, сравнить, перейти, вызвать. В курсе «инструкция» означает инструкцию языка C++, поэтому машинная называется командой. [Машинный код](extra/asm-basics/notes.md).

<a id="flags-register"></a>**Регистр флагов** (flags register) — биты процессора, которые команды выставляют попутно, как побочный результат: получился ли ноль, отрицателен ли результат, был ли перенос. Сравнение только выставляет флаги, решение по ним принимает следующая команда. [Машинный код](extra/asm-basics/notes.md).

<a id="conditional-jump"></a>**Условный переход** (conditional jump) — команда `je`, `jne`, `jl`, `jg` и подобные: перейти по адресу, если флаги сложились нужным образом. Знаковое и беззнаковое сравнения собираются в разные переходы. [Машинный код](extra/asm-basics/notes.md).

<a id="stack-pointer"></a>**Указатель стека** (stack pointer) — регистр `rsp`, хранящий адрес вершины стека; выделить память на стеке — вычесть из него число. [Машинный код](extra/asm-basics/notes.md).

<a id="return-address"></a>**Адрес возврата** (return address) — адрес команды, следующей за вызовом; `call` кладёт его на стек, `ret` снимает и передаёт туда управление. [Машинный код](extra/asm-basics/notes.md).

<a id="prologue-epilogue"></a>**Пролог и эпилог** (prologue, epilogue) — команды в начале и конце функции, которые заводят её кадр стека и снимают его. [Машинный код](extra/asm-basics/notes.md).

<a id="callee-saved"></a>**Callee-saved и caller-saved регистры** — часть calling convention: callee-saved функция обязана вернуть вызвавшей в прежнем виде, caller-saved вправе испортить, и сохраняет их при необходимости вызывающая сторона. [Машинный код](extra/asm-basics/notes.md).

<a id="shadow-space"></a>**Shadow space** — 32 байта, которые по соглашению Windows x64 вызывающая сторона обязана отвести на стеке под первые четыре аргумента, даже если те переданы в регистрах. [Машинный код](extra/asm-basics/notes.md).

<a id="indirect-call"></a>**Косвенный вызов** (indirect call) — вызов по адресу, взятому из регистра или из ячейки памяти, а не записанному в самой команде: так работают виртуальные функции, указатели на функции и вызовы через таблицу импорта. [Машинный код](extra/asm-basics/notes.md).

<a id="tail-call"></a>**Хвостовой вызов** (tail call) — оптимизация, при которой последний вызов функции превращается в переход: кадр не заводится, и вызванная функция возвращается сразу в вызвавшую вызвавшего. [Машинный код](extra/asm-basics/notes.md).

<a id="att-intel"></a>**Синтаксис AT&T и Intel** — две записи одних и тех же команд x86-64. В AT&T приёмник стоит справа, у регистров `%`, у констант `$`; в Intel приёмник слева и приставок нет. `objdump` по умолчанию печатает AT&T, MSVC и Compiler Explorer — Intel. [Машинный код](extra/asm-basics/notes.md).

<a id="loader"></a>**Загрузчик** (loader) — часть ОС, которая превращает исполняемый файл в работающий процесс. [Загрузка процесса](extra/process-loading/notes.md).

<a id="pe-elf"></a>**PE и ELF** (Portable Executable, Executable and Linkable Format) — форматы исполняемых файлов и библиотек Windows и Linux. [Загрузка процесса](extra/process-loading/notes.md).

<a id="entry-point"></a>**Точка входа** (entry point) — адрес, с которого ОС начинает выполнение процесса; это стартовый код библиотеки, а не `main`. [Загрузка процесса](extra/process-loading/notes.md).

<a id="relocation"></a>**Релокация** (relocation) — место в коде или данных, куда загрузчик или линкер вписывает настоящий адрес. [Загрузка процесса](extra/process-loading/notes.md).

<a id="import-table"></a>**Таблица импорта** (import table) — список функций, которые модуль берёт из библиотек, и ячейки под их адреса: IAT на Windows, GOT и PLT на Linux. [Загрузка процесса](extra/process-loading/notes.md).

<a id="lazy-binding"></a>**Ленивое связывание** (lazy binding) — адрес импортируемой функции ищется при первом вызове, а не при загрузке. [Загрузка процесса](extra/process-loading/notes.md).

<a id="aslr"></a>**ASLR, address space layout randomization** — загрузка модулей по случайным адресам, чтобы атакующий не знал, где лежит код. [Загрузка процесса](extra/process-loading/notes.md).

<a id="pic"></a>**PIC и PIE** (position-independent code, position-independent executable; по-русски — позиционно-независимый код) — код, который работает с любого адреса загрузки. [Загрузка процесса](extra/process-loading/notes.md).

<a id="siof"></a>**Static initialization order fiasco** — порядок инициализации глобальных объектов из разных единиц трансляции не определён, и один может обратиться к другому до его конструктора. Лекция 2.

<a id="system-call"></a>**Системный вызов** (system call) — обращение программы к ядру ОС: открыть файл, выделить память, создать поток. Лекция 2.

<a id="virtual-memory"></a>**Виртуальная память** (virtual memory) — каждый процесс видит своё адресное пространство, а процессор по таблице страниц переводит виртуальные адреса в физические. [Память процесса изнутри](extra/process-memory/notes.md).

<a id="page-fault"></a>**Page fault** (по-русски — ошибка страницы, страничное прерывание) — обращение к странице, которой сейчас нет в физической памяти; ОС подгружает её или останавливает процесс. [Память процесса изнутри](extra/process-memory/notes.md).

<a id="commit-reserve"></a>**Reserve и commit** — два шага выделения памяти в ОС: зарезервировать диапазон адресов и пообещать под него память (commit). Физические страницы появляются ещё позже, при первом обращении. [Память процесса изнутри](extra/process-memory/notes.md).

<a id="guard-page"></a>**Сторожевая страница** (guard page) — недоступная страница за концом стека: обращение к ней превращает переполнение в понятную ошибку. [Память процесса изнутри](extra/process-memory/notes.md).

<a id="cache-line"></a>**Кэш-линия** (cache line) — порция в 64 байта, которой память обменивается с кэшем процессора. [Кэш процессора](extra/cpu-cache/notes.md).

<a id="cache-miss"></a>**Промах кэша** (cache miss) — нужных данных в кэше нет, и процессор ждёт памяти. [Кэш процессора](extra/cpu-cache/notes.md).

<a id="cache-locality"></a>**Локальность** (locality, cache locality) — свойство программы обращаться к близким адресам подряд, благодаря которому работает кэш. Лекция 13.

<a id="prefetch"></a>**Предвыборка** (prefetch) — процессор заранее загружает в кэш данные, к которым программа, судя по шагу обхода, скоро обратится. [Кэш процессора](extra/cpu-cache/notes.md).

<a id="false-sharing"></a>**False sharing** (по-русски — ложное разделение) — потоки пишут в разные переменные, лежащие в одной кэш-линии, и мешают друг другу. [Кэш процессора](extra/cpu-cache/notes.md).

<a id="tlb"></a>**TLB, translation lookaside buffer** — кэш процессора для переводов виртуальных адресов в физические. [Кэш процессора](extra/cpu-cache/notes.md).

<a id="vectorization"></a>**Векторизация** (vectorization) — оптимизация, при которой одна команда процессора (SIMD) обрабатывает несколько элементов сразу. Лекция 7.

## Инструменты

<a id="sanitizer"></a>**Санитайзер** (sanitizer) — режим компилятора, который встраивает в программу проверки, срабатывающие во время выполнения. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

<a id="asan"></a>**ASan, AddressSanitizer** — санитайзер ошибок памяти: выход за границы, use-after-free, double free. Лекция 1.

<a id="ubsan"></a>**UBSan, UndefinedBehaviorSanitizer** — санитайзер арифметического и другого UB: переполнение, сдвиг, невыровненный доступ. Лекция 1.

<a id="tsan"></a>**TSan, ThreadSanitizer** — санитайзер гонок данных. Лекция 15.

<a id="lsan"></a>**LSan, LeakSanitizer** — санитайзер утечек памяти; на Windows не работает. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

<a id="shadow-memory"></a>**Теневая память** (shadow memory) — служебная память ASan, где на каждые 8 байт программы записано, сколько из них можно трогать. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

<a id="redzone"></a>**Красная зона** (redzone) — недоступные байты, которые ASan ставит вокруг каждого блока, чтобы поймать выход за границу. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

<a id="breakpoint"></a>**Точка останова** (breakpoint) — место, где отладчик остановит программу. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

<a id="watchpoint"></a>**Точка останова по данным** (data breakpoint, watchpoint) — остановка при записи в заданный адрес. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

<a id="call-stack"></a>**Стек вызовов** (call stack) — цепочка вызовов, которая привела в текущую точку. [Санитайзеры и отладчик](extra/sanitizers-debugger/notes.md).

## Git

<a id="repository"></a>**Репозиторий** (repository) — каталог проекта вместе со всей его историей; история лежит в подкаталоге `.git` и больше нигде. [Git: минимум на каждый день](extra/git-basics/notes.md).

<a id="working-tree"></a>**Рабочий каталог** (working tree) — файлы проекта в том виде, в каком они сейчас лежат на диске. Одна из трёх зон git — вместе с индексом и репозиторием. [Git](extra/git-basics/notes.md).

<a id="git-index"></a>**Индекс** (index, staging area) — зона между рабочим каталогом и историей: правки, отобранные командой `git add`, из которых будет собран следующий коммит. [Git](extra/git-basics/notes.md).

<a id="commit"></a>**Коммит** (commit) — записанное состояние проекта целиком плюс ссылка на родителя, автор и сообщение. Точка, в которую можно вернуться. [Git](extra/git-basics/notes.md).

<a id="branch"></a>**Ветка** (branch) — подвижный указатель на коммит: сделан коммит — указатель переехал вперёд. Завести ветку стоит одной записи. [Git](extra/git-basics/notes.md).

<a id="head"></a>**HEAD** — указатель «вы находитесь здесь»: обычно на ветку, а через неё на коммит. [Git](extra/git-basics/notes.md).

<a id="merge"></a>**Слияние** (merge) — объединение двух веток; даёт коммит с двумя родителями. [Git](extra/git-basics/notes.md).

<a id="merge-conflict"></a>**Конфликт слияния** (merge conflict) — один и тот же кусок файла изменён с обеих сторон, и выбрать за автора git не может: он оставляет в файле оба варианта. [Git](extra/git-basics/notes.md).

<a id="remote"></a>**Удалённый репозиторий** (remote) — вторая копия истории, обычно на сервере; имя по умолчанию — `origin`. Метка `origin/main` показывает, где сервер стоял при последнем разговоре с ним. [Git](extra/git-basics/notes.md).

<a id="snapshot"></a>**Снимок** (snapshot) — модель хранения git: коммит ссылается не на список правок, а на полный перечень файлов проекта на тот момент. Отсюда мгновенное переключение веток. [Git](extra/git-basics/notes.md).

<a id="git-object"></a>**Объект git** (git object) — единица хранения, адресуемая хешем содержимого: blob (содержимое файла), дерево (tree) — перечень файлов каталога, — коммит и тег. Одинаковое содержимое хранится в одном экземпляре. [Git](extra/git-basics/notes.md).

<a id="delta"></a>**Дельта** (delta) — запись изменения как разницы с другой версией. Git считает дельты на лету для показа и сжимает ими packfile, но моделью хранения они не являются. [Git](extra/git-basics/notes.md).

<a id="packfile"></a>**Packfile** — файл, в который git упаковывает множество объектов со сжатием и дельтами между похожими. [Git](extra/git-basics/notes.md).

## Текст и кодировки

<a id="code-point"></a>**Кодовая точка** (code point) — номер символа в Юникоде, от U+0000 до U+10FFFF. [Строки и кодировки](extra/text-encodings/notes.md).

<a id="code-unit"></a>**Кодовая единица** (code unit) — минимальная порция кодировки: байт в UTF-8, 16 бит в UTF-16. Кодовая точка занимает одну или несколько. [Строки и кодировки](extra/text-encodings/notes.md).

<a id="grapheme"></a>**Графема** (grapheme cluster) — то, что человек видит как один символ; может состоять из нескольких кодовых точек. [Строки и кодировки](extra/text-encodings/notes.md).

<a id="surrogate"></a>**Суррогатная пара** (surrogate pair) — две кодовые единицы UTF-16, которыми записывается кодовая точка за пределами первых 65536. [Строки и кодировки](extra/text-encodings/notes.md).

<a id="code-page"></a>**Кодовая страница** (code page) — однобайтовая кодировка Windows, например 1251 для кириллицы. [Строки и кодировки](extra/text-encodings/notes.md).

<a id="locale"></a>**Локаль** (locale) — настройки языка и региона: кодировка, формат чисел и дат, правила сравнения строк. [Строки и кодировки](extra/text-encodings/notes.md).

<a id="mojibake"></a>**Кракозябры** (mojibake) — текст, прочитанный не в той кодировке. [Строки и кодировки](extra/text-encodings/notes.md).
