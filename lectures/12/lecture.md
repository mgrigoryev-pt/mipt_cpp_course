# Лекция 12. `auto` и `decltype`: кто пишет типы

> Конспект к лекции для самостоятельного чтения. Слайды (`slides.md`) повторяют структуру, конспект подробнее объясняет «почему».

## 0. О чём эта лекция

`auto` мы уже использовали много раз — в циклах (`for (const auto& x : v)`), для лямбд (`auto f = [](int){...}`), для итераторов (`auto it = v.begin()`). Каждый раз это работало, и мы не задумывались, что происходит.

Сегодня задумаемся — и обнаружим, что `auto` делает **не совсем то**, чего можно было бы ожидать. Он не просто «подставляет тип справа», а **упрощает** его: отбрасывает `const` и ссылочность. В большинстве случаев это правильно, но иногда именно это ломает код, и тогда нужен более точный инструмент — `decltype`.

Разберём по порядку:

1. **`auto`** — передаём вывод типа компилятору. Где это уместно, как работает механизм.
2. **Что `auto` теряет.** Отбрасывание `const`/`&`, восстановление вручную, ловушка с фигурными скобками.
3. **`auto` за пределами переменных** — возвращаемый тип, trailing return type, параметры функций (C++20).
4. **`decltype`** — инструмент для случаев, где нужен точный тип. Две главные задачи: назвать безымянный тип и вывести тип из выражения в шаблоне.
5. **`decltype(auto)`** — синтез: удобство `auto` плюс точность `decltype`.

К концу лекции вы должны безошибочно выбирать между `auto`, `auto&`, `const auto&`, `decltype(expr)` и `decltype(auto)` — и знать два подвоха, на которых спотыкаются чаще всего.

## 1. `auto` — передаём работу компилятору

C++ статически типизирован: у каждой переменной есть тип, известный компилятору. Обычно этот тип пишет программист. Но иногда написанное не несёт новой информации:

```cpp
std::vector<std::pair<std::string, int>>::const_iterator it = v.begin();
```

Тип полностью определён правой частью — `v.begin()` не может вернуть ничего другого. Программист просто переписывает то, что компилятор и так знает. `auto` убирает это дублирование:

```cpp
auto it = v.begin();     // тот же тип, в пять раз короче
```

### Три случая, где `auto` уместен

- **Тип полностью определён правой частью.** Итераторы, результаты функций с говорящими именами. Писать полное имя — шум.
- **Тип невыразим.** У лямбды нет имени типа (лекция 10). Без `auto` её вообще нельзя сохранить в переменную.
- **Тип может измениться.** Если завтра поменять `std::vector` на `std::deque`, переменные с `auto` подстроятся автоматически; явно написанные типы придётся править руками.

Обратная сторона: `auto` **скрывает** тип от читателя. Если тип несёт смысл — например, `int32_t` против `int64_t` в арифметике, где важно переполнение, — лучше написать явно. Правило: `auto`, когда тип очевиден или неважен; явный тип, когда он часть контракта.

### Как это работает

Важно понимать, что `auto` — это **не** динамическая типизация. Тип фиксируется на этапе компиляции, никакого рантайм-механизма нет. Просто его вычисляет компилятор, а не пишет человек.

Механизм при этом ровно тот же, что вывод `T` в шаблонной функции — мы разбирали его в лекции 9:

```cpp
template <typename T> void f(T param);
f(expr);           // T выводится из expr

auto x = expr;     // тип x выводится по тем же правилам
```

Это не аналогия для запоминания — в стандарте это описано буквально одними и теми же правилами. Поэтому, зная поведение шаблонного вывода, вы автоматически знаете поведение `auto`, и наоборот.

## 2. Что `auto` теряет по дороге

Из того, что `auto` работает по правилам шаблонного вывода, следует неочевидное: он **не копирует** тип выражения буквально, а **упрощает** его.

```cpp
int i = 5;
const int& r = i;

auto a = r;        // int  —  ни const, ни ссылки!
a = 100;           // компилируется; меняем свою копию, i не тронут
```

Компилятор отбросил и `const`, и `&`. У этого есть логика: мы объявляем **новую переменную**, она своя собственная. Const-ность источника к ней не относится (мы не обязаны наследовать его ограничения), ссылочность тоже (это отдельный объект, а не псевдоним).

Но с точки зрения читателя выглядит как молчаливое несоответствие: написали `auto a = r`, где `r` — константная ссылка, а получили изменяемую копию. Если вы рассчитывали работать с тем же объектом — получили не то, и компилятор не предупредит.

### Восстанавливаем то, что нужно

`auto` сам по себе всегда даёт **значение**. Ссылку и const запрашивают явно, добавляя их к `auto`:

```cpp
int i = 5;
const int ci = 10;

auto  x = ci;        // int          — копия (const отброшен)
auto& y = i;         // int&         — ссылка
const auto& z = ci;  // const int&   — ссылка на const
auto* p = &i;        // int*         — указатель
```

Отсюда три идиомы для циклов, которые нужно различать не задумываясь:

```cpp
for (const auto& item : container) { /* только читаем, не копируем */ }
for (auto& item : container)       { /* меняем элементы на месте */ }
for (auto item : container)        { /* нужна независимая копия */ }
```

**`const auto&` — правильный дефолт для чтения.** Не копирует (важно для больших объектов вроде `std::string`) и не даёт случайно изменить контейнер. Если элементы дешёвые (числа, маленькие структуры) — `auto` по значению тоже нормально и иногда даже быстрее.

Частая ошибка новичков — написать `for (auto x : big_vector_of_strings)`: каждая итерация копирует строку.

### Второй сюрприз: фигурные скобки

Поведение `auto` с brace-инициализацией неинтуитивно:

```cpp
auto x = 5;              // int         — ok
auto y(5);               // int         — ok
auto z{5};               // int с C++17 (до C++17 было std::initializer_list<int>!)
auto w = {1, 2, 3};      // std::initializer_list<int>  ← сюрприз
```

Последняя строка — классическая ловушка. Многие пишут так, рассчитывая получить массив или вектор, а получают `initializer_list` — тип-обёртку, которая **не владеет** данными и живёт только до конца выражения. Дальше с ней почти ничего нельзя делать.

История здесь запутанная: правила для `auto` плюс `{}` менялись между C++11, C++14 и C++17. Именно поэтому в этом месте так легко ошибиться.

**Правило:** пишите `auto x = expr;` либо `auto x = T{...};` с явно указанным `T`. Голый brace-init после `auto` без типа — почти всегда не то, что вы имели в виду.

## 3. `auto` за пределами переменных

### Возвращаемый тип функции (C++14)

Компилятор может вывести и тип возврата — из выражений в `return`:

```cpp
auto sum(int a, int b) {
    return a + b;                 // компилятор видит: int
}
```

Особенно полезно в шаблонах, где тип результата заранее записать трудно:

```cpp
template <typename T, typename U>
auto add(T a, U b) {
    return a + b;                 // тип зависит от T, U и правил promotion
}

add(2, 3);        // int
add(2, 3.0);      // double
```

Цена такой записи: тело функции должно быть **видно в точке вызова**, иначе компилятору неоткуда взять тип. На практике это значит — определение в заголовочном файле. Поэтому `auto`-возврат живёт в основном у `inline` и шаблонных функций.

Ограничение: если в функции несколько `return` с **разными** типами — CE. Все ветви должны давать один тип.

### Trailing return type

Тип можно написать после параметров, за стрелкой:

```cpp
auto sum(int a, int b) -> int { return a + b; }
```

Для этого примера запись бессмысленна — обычный `int sum(int, int)` короче. Но в шаблонном коде она решает конкретную проблему: **справа от `->` параметры уже объявлены**, и на них можно ссылаться:

```cpp
template <typename T, typename U>
auto add(T a, U b) -> decltype(a + b);
```

В обычной записи это невозможно:

```cpp
decltype(a + b) add(T a, U b);    // CE: a и b ещё не объявлены
```

С появлением `auto`-возврата (C++14) и `decltype(auto)` нужда в trailing return type сильно упала, но в шаблонной библиотечной инфраструктуре запись всё ещё встречается — её нужно узнавать.

### `auto` в параметрах (C++20)

С C++20 `auto` можно писать прямо в параметрах:

```cpp
auto add(auto a, auto b) { return a + b; }
```

Это **сокращённая запись шаблона** (abbreviated function template). Компилятор разворачивает её в:

```cpp
template <typename T, typename U>
auto add(T a, U b) { return a + b; }
```

Каждое `auto` в параметрах становится отдельным неявным шаблонным параметром. Никакой новой семантики — только компактность.

Особенно приятно вместе с концептами:

```cpp
auto sum(std::integral auto a, std::integral auto b) { return a + b; }

sum(2, 3);          // ok
sum(2.0, 3.0);      // CE: double не удовлетворяет std::integral
```

Это самый короткий способ написать ограниченный шаблон. Концепты — большая отдельная тема, в курс она не входит; здесь достаточно узнавать синтаксис.

## 4. `decltype` — когда нужен точный тип

Вернёмся к проблеме из раздела 2: `auto` упрощает тип, отбрасывая `const` и `&`. Обычно это удобно. Но иногда нужно ровно обратное — **точный** тип, каким он есть.

Для этого есть `decltype(expr)`:

```cpp
int x = 5;
const int& r = x;

auto        a = r;   // int         — упрощено
decltype(r) b = x;   // const int&  — точно как у r
```

Итого два инструмента для двух разных задач:

- **`auto`** — «мне нужно **значение**, тип посчитай сам».
- **`decltype(expr)`** — «мне нужен **ровно тот тип**, что у этого выражения».

Посмотрим на две задачи, где без `decltype` не обойтись.

### Задача 1: назвать безымянный тип

Мы это уже видели в лекции 10. У лямбды нет имени типа — компилятор генерирует анонимный класс. Но иногда тип нужен как **шаблонный аргумент**:

```cpp
auto cmp = [](int a, int b) { return a > b; };

std::set<int, decltype(cmp)> s(cmp);
std::priority_queue<int, std::vector<int>, decltype(cmp)> q(cmp);
```

`std::set` требует тип компаратора как второй шаблонный параметр. Написать имя анонимного класса невозможно — его не существует в коде. `decltype(cmp)` — единственный способ на него сослаться.

Это **самое частое** применение `decltype` в прикладном коде. Если вы его встретите — почти наверняка речь о лямбде.

### Задача 2: тип из выражения в шаблоне

```cpp
template <typename Container>
auto first(const Container& c) -> decltype(c[0]) {
    return c[0];
}
```

Мы хотим вернуть **ровно то**, что даёт `c[0]`. Для `std::vector<int>` это `int&`. Для `std::vector<bool>` — прокси-объект (`vector<bool>` не хранит настоящие `bool` и возвращает обёртку). Для `std::map` — что-то третье.

Написать этот тип руками нельзя: он зависит от `Container`, который станет известен только при инстанцировании. `decltype(c[0])` перекладывает эту работу на компилятор и гарантирует, что не потеряется ссылочность и не произойдёт неявной конверсии.

С `auto`-возвратом из C++14 это часто пишется проще: `auto first(const Container& c) { return c[0]; }` — но тогда сработает `auto`-упрощение, и ссылка потеряется. Об этом — следующий раздел.

### Подвох: имя или выражение

У `decltype` есть тонкость, которая удивляет всех при первой встрече:

```cpp
int x = 5;

decltype(x)   a;      // int   — «тип переменной x»
decltype((x)) b = x;  // int&  — «тип выражения (x)»
```

Разница только в скобках, а результат разный. Правило такое:

- `decltype` от **имени** (`decltype(x)`) даёт **объявленный тип** переменной. Просто `int`.
- `decltype` от **выражения** (`decltype((x))`) учитывает **категорию значения**. А `(x)` — это lvalue-выражение, поэтому тип получается `int&`.

Формально `(x)` синтаксически не имя, а выражение в скобках — отсюда разное поведение.

На практике этим никто не пользуется специально. Но знать стоит: иначе однажды упрётесь в ошибку компиляции, которая выглядит абсолютно необъяснимо, пока не вспомните про скобки.

## 5. `decltype(auto)` — синтез

Соберём, к чему мы пришли:

- **`auto`** удобно пишется (тип берётся из инициализатора), но **упрощает** — теряет ссылки и const.
- **`decltype(expr)`** точен, но требует **повторить выражение** в объявлении типа.

Второе особенно раздражает при возврате из функции:

```cpp
int& get_ref();

auto a = get_ref();                  // int — ссылка потеряна, получили копию
decltype(get_ref()) b = get_ref();   // точно, но вызов записан дважды
```

Дублирование `get_ref()` — не только некрасиво, но и опасно: если выражение сложное и вы поправите его в одном месте, забыв про другое, получите рассинхронизацию.

C++14 решает это через **`decltype(auto)`**: «выведи тип так, как это сделал бы `decltype`, но применённый к инициализатору».

```cpp
int x = 5;
int& get_ref() { return x; }

auto           a = get_ref();   // int   — копия
decltype(auto) b = get_ref();   // int&  — ссылка сохранена

b = 100;                         // меняем x через ссылку!
```

Синтаксис от `auto` (выражение не дублируется), правила вывода от `decltype` (ничего не теряется).

### Где это реально нужно

Главное применение — **обобщённые обёртки**, которые обязаны вернуть ровно то, что вернула обёрнутая функция:

```cpp
template <typename F, typename... Args>
decltype(auto) call(F&& f, Args&&... args) {
    return std::forward<F>(f)(std::forward<Args>(args)...);
}
```

Если `f()` возвращает `int&` — `call(f)` тоже вернёт `int&`. С обычным `auto` обёртка «съела» бы ссылку, и вызывающий получил бы копию — то есть обёртка изменила бы семантику того, что оборачивает. Для прозрачной обёртки это неприемлемо.

`std::forward` в этом примере — идеальная передача с лекции 11: аргументы уезжают в `f` тем же, чем пришли. `decltype(auto)` доводит ту же мысль до возвращаемого значения, и вместе они дают обёртку, которую не видно снаружи.

В прикладном коде `decltype(auto)` встречается **редко** — это инструмент для написания библиотечной инфраструктуры (обёртки, декораторы, forwarding-функции). Знать полезно, чтобы понимать чужой код.

### Осторожно с локальными переменными

`decltype(auto)` сохраняет ссылочность — значит, можно случайно вернуть ссылку на локальный объект:

```cpp
decltype(auto) bad() {
    int local = 42;
    return (local);       // decltype((local)) == int&  →  dangling reference!
}
```

Те самые скобки из предыдущего раздела. Без них было бы `int` (копия), со скобками — `int&` на умирающую переменную. Это одна из причин, по которой `decltype(auto)` не стоит применять без явной необходимости.

## Итоги

Сводная таблица выбора:

| Нужно | Пишем |
|---|---|
| Значение, тип очевиден справа | `auto` |
| Читать элементы, не копируя | `const auto&` |
| Менять элементы на месте | `auto&` |
| Точный тип выражения (назвать тип лямбды) | `decltype(expr)` |
| Вернуть ровно то, что вернул вызов | `decltype(auto)` |

Главная мысль лекции: **`auto` и `decltype` решают разные задачи**, и путать их дорого.

- **`auto`** — «мне нужно значение». Отбрасывает `const` и `&`. Это **фича**, а не баг, но о ней нужно помнить: ссылку и const запрашивают явно через `auto&` / `const auto&`.
- **`decltype`** — «мне нужен ровно этот тип». Сохраняет всё. Два главных применения: назвать безымянный тип (лямбды) и вывести тип из выражения в шаблоне.
- **`decltype(auto)`** — `auto`-синтаксис с `decltype`-точностью. Для прозрачных обёрток.

И два подвоха, на которых спотыкаются чаще всего:

- `auto w = {1, 2, 3}` даёт `std::initializer_list<int>`, а не контейнер.
- `decltype((x))` со скобками даёт `int&`, а `decltype(x)` без скобок — `int`.

Следующая лекция — **итераторы, контейнеры и алгоритмы**:

- Итератор как обобщённый указатель, категории итераторов
