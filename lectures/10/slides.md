# 1. Лямбды как функторы

К этому моменту мы знаем:

- Функторы (лекция 5): класс с `operator()` ведёт себя как функция и может иметь состояние
- Шаблоны (лекции 8–9): можно писать обобщённый код

**Лямбда** — это синтаксический сахар над **шаблонным функтором**, который компилятор генерирует за вас.

```cpp
auto add5 = [](int x) { return x + 5; };
add5(10);     // 15
```

`add5` — это объект анонимного класса с `operator()`.

---

## Что компилятор разворачивает

```cpp
auto add5 = [](int x) { return x + 5; };
```

эквивалентно примерно:

```cpp
class __Lambda_42 {
public:
    auto operator()(int x) const { return x + 5; }
};

__Lambda_42 add5;
```

Каждая лямбда — **отдельный тип**. Даже две лямбды с одинаковым телом имеют разные типы.

---

## Зачем это нужно

Лямбды короткие и **локальные**:

```cpp
std::vector<int> v = {3, 1, 4, 1, 5};
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
```

vs. отдельный класс:

```cpp
struct DescendingCmp {
    bool operator()(int a, int b) const { return a > b; }
};
std::sort(v.begin(), v.end(), DescendingCmp{});
```

Одинаковый результат, лямбда выразительнее.

# 2. Списки захвата

Лямбда может **захватить** локальные переменные:

```cpp
int x = 10;
auto add_x = [x](int n) { return n + x; };
add_x(5);   // 15
```

`[x]` — это **список захвата**. Захваченные переменные становятся **полями** генерируемого класса.

---

## By value vs by reference

```cpp
int x = 10;

auto by_val = [x](int n) { return n + x; };       // копия x
auto by_ref = [&x](int n) { return n + x; };      // ссылка на x

x = 100;
by_val(0);   // 10 (старая копия)
by_ref(0);   // 100 (свежее значение)
```

`[x]` — захват **по значению** (копия в момент создания лямбды).
`[&x]` — захват **по ссылке** (видит изменения).

---

## Захват по умолчанию

```cpp
int a = 1, b = 2;

auto f1 = [=](int n) { return n + a + b; };   // все локальные по значению
auto f2 = [&](int n) { a = b = n; return a; };// все локальные по ссылке
auto f3 = [=, &b](int n) { b = n; return a; };// a по значению, b по ссылке
```

`[=]` — захват **всех** по значению.
`[&]` — захват **всех** по ссылке.
Можно комбинировать: `[=, &b]` — все по значению, кроме `b`.

В современном стиле часто избегают `[=]` и `[&]` — лучше явный список захвата.

---

## Подвох: dangling reference

```cpp
auto make_lambda() {
    int x = 10;
    return [&x] { return x; };     // x умрёт после возврата!
}

auto f = make_lambda();
f();    // UB
```

Захват по ссылке требует, чтобы захваченные переменные **жили** дольше лямбды.

**Правило:** если лямбда переживёт текущую функцию — захватывайте по значению.

# 3. Лямбды как объекты

Поскольку лямбда — это объект, её можно:

```cpp
auto f = [](int x) { return x * 2; };

f(5);                  // вызов
auto g = f;            // копия (если захваты копируются)
sizeof(f);             // размер — определяется захватами
```

Лямбда без захватов имеет **размер 1 байт** (пустой класс).
С захватами — размер зависит от типов и числа захваченных переменных.

---

## `auto` обязателен

Тип лямбды у компилятора — анонимный, его нельзя написать руками:

```cpp
auto f = [](int x) { return x * 2; };       // ok, auto
SomeType f = [](int x) { return x * 2; };   // невозможно — нет имени типа
```

Поэтому лямбды всегда живут под `auto`. Если нужно передать лямбду как параметр функции — есть `std::function` (см. дальше) или шаблоны.

---

## `decltype` для безымянного типа

Если всё-таки нужно **сослаться на тип** лямбды (как на шаблонный аргумент, как тип поля), есть `decltype(expr)` — оно даёт «тип выражения»:

```cpp
auto cmp = [](int a, int b) { return a > b; };

std::set<int, decltype(cmp)> s(cmp);     // тип компаратора set'а
std::priority_queue<int, std::vector<int>, decltype(cmp)> q(cmp);
```

`decltype(cmp)` — это тот самый анонимный тип. Полный разбор `decltype` (как и `auto`) — на лекции 12.

---

## Лямбда без захватов конвертируется в указатель

Только лямбды **без захватов** имеют конверсию в обычный указатель на функцию:

```cpp
auto plain = [](int x) { return x * 2; };
int (*fp)(int) = plain;        // ok, конверсия

auto capturing = [n = 5](int x) { return x + n; };
int (*fp2)(int) = capturing;   // CE: нельзя
```

Это полезно для интеропа с C-API, которые ожидают указатель на функцию. Что делать, если захваты всё-таки нужны — раздел 8.

# 4. Захват полей класса и `this`

Внутри метода класса захват полей работает **через `this`**:

```cpp
class Counter {
    int count_ = 0;
public:
    auto make_incrementer() {
        return [this] { ++count_; };   // захватили this
    }
};
```

`[this]` — захват указателя на объект. Лямбда видит **все поля и методы** через `this`, как обычный метод.

---

## Подвох с `this`

`[this]` — это указатель. Если объект умрёт раньше лямбды — UB:

```cpp
auto f = []() {
    Counter c;
    return c.make_incrementer();   // лямбда захватила &c
};                                  // c умирает здесь

f()();   // UB: используем умерший объект
```

С C++17 есть `[*this]` — захват **копии** всего объекта:

```cpp
auto make_inc() {
    return [*this] { /* копия объекта */ };
}
```

# 5. Захват с инициализацией (C++14)

Можно создать **новое имя** в захвате с произвольным выражением:

```cpp
int x = 10;
auto f = [y = x * 2](int n) { return n + y; };   // y = 20
f(5);   // 25
```

Это особенно полезно для **move-захвата** (мы это увидим в лекции про move):

```cpp
auto ptr = std::make_unique<int>(42);
auto f = [p = std::move(ptr)] { return *p; };
// теперь ptr пуст, p — внутри лямбды
```

`std::unique_ptr` не копируется — и только такой захват позволяет его забрать.

# 6. Шаблонные лямбды

С C++14 — лямбды с `auto` параметром:

```cpp
auto print = [](auto x) { std::cout << x << ' '; };
print(42);        // int
print(3.14);      // double
print("hello");   // const char*
```

`auto` здесь — синоним `typename T` для шаблонной функции. Компилятор генерирует **шаблонный `operator()`** в анонимном классе:

```cpp
template <typename T>
auto operator()(T x) { ... }
```

---

## Явный шаблон (C++20)

С C++20 можно писать шаблонный синтаксис прямо в лямбде:

```cpp
auto first = []<typename T>(const std::vector<T>& v) {
    return v.front();
};

first(std::vector{1, 2, 3});   // int
```

Полезно, когда нужно достать тип `T` из контейнера или ограничить его концептами.

# 7. `std::function` — универсальный callable

У каждой лямбды свой тип. А что если нужно **хранить** разные лямбды в одной переменной или передать в функцию?

```cpp
std::vector<???> callbacks;     // что положить — все лямбды разных типов
```

Решение — **`std::function<Sig>`** — стирающий типы контейнер для любого callable.

---

## Использование

```cpp
#include <functional>

std::function<int(int, int)> op;     // принимает любой callable (int, int) → int

op = [](int a, int b) { return a + b; };   // лямбда
std::cout << op(3, 5) << '\n';             // 8

int sub(int a, int b) { return a - b; }
op = sub;                                   // обычная функция
std::cout << op(10, 3) << '\n';            // 7

struct Functor { int operator()(int a, int b) { return a * b; } };
op = Functor{};                             // функтор
std::cout << op(4, 6) << '\n';             // 24
```

---

## Что внутри

`std::function` использует **type erasure**: внутри хранится callable любого типа, наружу торчит единый интерфейс.

Цена:

- **Heap allocation** для callable, который не помещается в SBO-буфер (~16 байт)
- **Виртуальный вызов** при `operator()` (один indirect call)
- Дороже лямбды-функтора, если тип известен на компиляции

**Правило:**

- Тип callable **известен и нужен один тип** → шаблонный параметр или лямбда напрямую
- Нужно **хранить разные** callable в одной переменной/контейнере → `std::function`

---

## `std::function` в API

```cpp
class EventBus {
public:
    void subscribe(std::function<void(const Event&)> handler);
};

// каждый подписчик решает сам, что делать с событием
bus.subscribe([&](const Event& e) { rules.Check(e); });
bus.subscribe([&](const Event& e) { stats.Count(e); });
bus.subscribe(&write_to_log);          // и обычная функция тоже
```

`std::function` — стандартный способ принять «любой callable» в **API классов**: `EventBus` не может быть шаблоном по типам всех подписчиков, ведь их список собирается в рантайме.

В шаблонном коде обычно лучше template-параметр для callable — без стирания типа.

# 8. Лямбда и C-API: контекст через `void*`

Так подписываются на поток событий системные и сторонние C-библиотеки:

```cpp
struct lib_event { int pid; const char* name; };

void lib_subscribe(void (*cb)(const lib_event*, void*), void* ctx);
```

У указателя на функцию **нет состояния** — это просто адрес кода. Поэтому контекст едет вторым параметром: библиотека вернёт `ctx` без изменений в каждый вызов колбэка.

**Правило:** в C-API код и состояние передаются отдельно.

---

## Лямбда с захватами туда не проходит

```cpp
class Collector {
    int seen_ = 0;
public:
    void subscribe() {
        lib_subscribe([this](const lib_event*, void*) { ++seen_; }, this);
    }
};
```

```
error: cannot convert '...<lambda(const lib_event*, void*)>'
       to 'void (*)(const lib_event*, void*)'
```

Захват `[this]` — это **поле** анонимного класса. Значит перед нами объект, а не функция, и адресом кода его не представить (раздел 3).

---

## Решение: статическая функция-трамплин

Свободная или статическая функция нужной сигнатуры: приводит `ctx` обратно к типу объекта и зовёт метод.

```cpp
class Collector {
public:
    void subscribe() { lib_subscribe(&trampoline, this); }
private:
    void on_event(const lib_event& e) { /* обычный C++-код */ }

    static void trampoline(const lib_event* e, void* ctx) noexcept {
        static_cast<Collector*>(ctx)->on_event(*e);
    }
};
```

У статического метода нет неявного `this` — конверсия проходит. Обратное приведение `void*` в `T*` — работа `static_cast` (лекция 3).

---

## Подвох: время жизни и адрес

В `ctx` уезжает голый адрес — библиотека за ним не следит и будет звать колбэк, пока подписка активна.

- Объект обязан **пережить подписку**: адрес локального или временного передавать нельзя
- Объект нельзя **перемещать** после регистрации — `ctx` будет указывать на старое место
- По той же причине опасен адрес элемента вектора: при росте буфер переедет

**Правило:** отписка — до разрушения объекта (обычно в деструкторе), сам объект — по стабильному адресу.

---

## Подвох: исключения и граница C

Исключение, вылетевшее из колбэка **сквозь кадры C**, — UB: разворачивать через них стек нельзя.

```cpp
static void trampoline(const lib_event* e, void* ctx) noexcept {
    try {
        static_cast<Collector*>(ctx)->on_event(*e);
    } catch (...) {
        // залогировать и вернуть управление библиотеке
    }
}
```

**Правило:** трамплин помечен `noexcept` и не бросает. Ошибку сохраняем в объекте и разбираем на C++-стороне.

---

## Если захватов нет — трамплин не нужен

Лямбда без захватов конвертируется в указатель на функцию (раздел 3), поэтому трамплином может быть она сама:

```cpp
void Collector::subscribe() {
    lib_subscribe(
        [](const lib_event* e, void* ctx) noexcept {
            static_cast<Collector*>(ctx)->on_event(*e);
        },
        this);
}
```

Захваты и не нужны: контекст уже приехал в `ctx`. А если параметра `void*` в C-API нет — состояние передать нечем, остаются глобальные переменные.

# Итоги лекции

- **Лямбда — это автогенерируемый функтор.** Компилятор разворачивает её в анонимный класс с `operator()`
- **Каждая лямбда — отдельный тип.** Хранится только под `auto`
- **Списки захвата:** by value `[x]`, by reference `[&x]`, по умолчанию `[=]`/`[&]`. Захват по ссылке требует следить за временем жизни
- **Захват с инициализацией** `[y = expr]` — для move и для произвольных выражений
- **`[this]`** — захват объекта. `[*this]` (C++17) — копия
- **Шаблонные лямбды:** `auto` параметр или явный `<typename T>` в C++20
- **`std::function`** — тип-обёртка для любого callable. Стирание типа, цена — heap alloc + indirect call
- **C-API:** контекст через `void*` + статический **трамплин**. Объект должен пережить подписку и не бросать исключений наружу
