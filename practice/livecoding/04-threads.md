# Лайв-кодинг «Умные указатели и потоки»

Одна программа — `threads.cpp`, — которая растёт маленькими шагами. Каждый
шаг добавляет одну конструкцию языка, и после каждого программа собирается
без предупреждений и печатает то, что указано в его «Проверке».

Шаг записан блоком комментария. Скопируйте его целиком и вставьте
в `threads.cpp` над тем местом, где будете писать: компилятору комментарий
не мешает, а условие остаётся перед глазами рядом с кодом. Начните с шапки —
она идёт в самое начало файла.

Банк опирается на лекцию 15. Блоки 1–2 — умные указатели, первая половина
лекции; блоки 3–5 — потоки, вторая.

## Шапка

```cpp
// Лайв-кодинг: умные указатели и потоки шаг за шагом
//
// Вы пишете одну программу — `threads.cpp` — маленькими шагами. Каждый шаг
// добавляет одну конструкцию языка, и после каждого программа собирается без
// предупреждений и печатает то, что указано в «Проверке».
//
// В «Проверке» — только то, что шаг добавил или изменил. Остальной вывод
// остаётся прежним.
//
// Каждая тема — отдельная функция, а `main` вызывает их по очереди. Так
// деструкторы одной темы печатают внутри неё, а не в конце программы.
//
// Печатает только главный поток и только тогда, когда рабочие потоки уже
// закончили. Поэтому порядок строк от запуска к запуску не меняется.
// Исключение одно — шаг, где число в выводе каждый раз своё; он говорит об
// этом сам.
//
// Имена берите из задания. По ним преподаватель сверяет код.
//
// Сверьте вывод сами и переходите дальше. Преподаватель подойдёт и посмотрит
// код. Если вывод не совпал или программа не собирается дольше двух-трёх минут
// — позовите его.
//
// Файл лежит отдельно от проекта nano-edr. Сборка и запуск на Windows:
//
//     clang++ -std=c++23 -Wall -Wextra threads.cpp -o threads.exe
//     threads.exe
//
// На Linux:
//
//     clang++ -std=c++23 -Wall -Wextra -pthread threads.cpp -o threads
//     ./threads
//
// Оптимизацию (`-O2`) не включайте: на шаге 16 она может спрятать ошибку,
// которую этот шаг показывает.
//
// Поля классов и структур инициализируйте в объявлении пустыми фигурными
// скобками: `int pid{};`, `std::string name_{};`.
```

## Блок 4. Общие данные и ожидание

### Шаг 16. Гонка данных

```cpp
// Шаг 16. Гонка данных
//
// Заведите константу `constexpr int kIterations = 1'000'000;` и напишите
// функцию `void CountProcessed()`:
// - в ней `int processed{}`;
// - лямбда `auto process` захватывает `processed` по ссылке и `kIterations`
//   раз выполняет `++processed`;
// - во вложенном блоке два потока: `std::jthread first{process};` и
//   `std::jthread second{process};`;
// - после блока напечатайте `expected:` и `2 * kIterations`, затем
//   `processed:` и `processed`.
//
// Вызовите функцию из `main` после `StopWatcher` и запустите программу
// несколько раз.
//
// Проверка — новая строка:
//
//     expected: 2000000
//
// Следом идёт строка `processed:`, и число в ней меняется от запуска
// к запуску и почти всегда меньше ожидаемого, например `processed: 1316062`.
// Оба потока пишут в одну переменную без синхронизации — это гонка данных,
// и это UB. `++processed` — чтение, сложение и запись, и между чтением и
// записью другой поток успевает записать своё. Изредка потоки не
// пересекаются, и число выходит ровным; это не значит, что ошибки нет.
//
// Где посмотреть: лекция 15, раздел 6.
```

// Шаг 20. Закрыть очередь

//
