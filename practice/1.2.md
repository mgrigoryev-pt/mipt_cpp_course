# Занятие 1.2. Односвязный список и разбор строки

> [Лекция 2](../lectures/02/lecture.md): указатели, память, RAII, `unique_ptr`.

Появляется первая структура данных, которую вы напишете сами, и первый тип
проекта — `Event`. Список проживёт в проекте шесть занятий, потом уступит место
кольцевому буферу, и на занятии 3.1 вы замерите, что от этого изменилось.

## Конфигурация

```bash
cmake --preset windows -D NANO_EDR_LESSON=1.2
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Что делают эти команды и откуда их
запускать — в [`project/README.md`](../project/README.md).

Набор тестов 1.1 остаётся подключённым, и это не случайность: он фиксирует
формат вывода детектов. Внутренности на этом занятии переписываются целиком,
и то, что вывод под `--quiet` остался побайтово тем же, — единственное
доказательство, что контракт не поехал.

## Куда это писать

Два новых файла в `src/`:

| | |
|---|---|
| `src/parse.cpp` | реализации из `parse.h` |
| `src/event_list.cpp` | реализации из `event_list.h` |

`CMakeLists.txt` править не нужно: библиотека `nano_edr_core` собирается
из всех `.cpp` в `src/`, кроме `main.cpp`, а выданные тесты линкуются с ней.
Но появление новых файлов — это изменение описания проекта, поэтому после него
нужна **пере**конфигурация: `cmake --preset windows -D …` ещё раз.

Реализовать нужно всё, что объявлено в заготовках, и ровно с теми подписями:

```
ParseFields  ParseEventLine  IsBlankOrComment
ListPushBack  ListPopFront  ListClear  EventList::~EventList
```

**Пока этих файлов нет, набор 1.2 не собирается** — компоновщик скажет
`unresolved external symbol` (на Linux — `undefined reference`) на каждую
из семи. Так выглядит начало занятия, а не поломка комплекта.

## Примитив (40 минут)

Односвязный список `EventList`: узел с указателем на следующий, вставка в конец,
обход, освобождение.

Порядок работы важен:

1. **Сначала на сырых указателях.** `new`, `delete`, `Node* next`. Цель —
   увидеть, как это устроено, и написать деструктор руками.
2. **Потом переписать владение на `std::unique_ptr`** и обсудить, что
   изменилось: где исчез `delete`, что стало с копированием, почему список
   теперь нельзя случайно скопировать.

Отдельно — почему **рекурсивное освобождение длинного списка опасно**. Цепочка
`unique_ptr` разбирается рекурсией: деструктор головы вызывает деструктор
следующего узла, и глубина стека равна длине списка. На тысяче узлов это
работает, на миллионе — нет.

## Проект

- **`struct Event`** — агрегат, ещё без методов: поля-строки `ts`, `type`, `pid`
  и вектор пар «ключ-значение».
- **Разбор строки** на пары «ключ-значение» прямым проходом по символам,
  с учётом кавычек. `cmdline="cmd /c wscript %TEMP%\a.js"` — одно значение
  с пробелами внутри, а не три поля.
- **Список хранит окно последних событий**: у него есть вместимость, и при
  переполнении самое старое уходит. Окно, а не архив.

## Дома

- Довести список до состояния «проходит выданные тесты»: пустой, один элемент,
  тысяча элементов, освобождение без утечек под санитайзером.
- Вырожденные входы разбора: незакрытая кавычка, `=` внутри значения,
  дубликаты ключей, ключ без значения, пустая строка.
- **Размер окна из командной строки:** `--window N`, по умолчанию 64. Ноль
  означает «без ограничения». Число разбирайте руками — `std::stoi` бросает
  исключение, а исключения это занятие 1.3.
- **Контекст детекта.** Окно пока никто не читает, и структура, которую только
  заполняют, ничего не доказывает. Печатайте перед каждым детектом два
  последних события из окна — время, тип, `pid`:

  ```
  [CTX]    -2: ts=1730000002000 type=process_start pid=1042
  [CTX]    -1: ts=1730000003000 type=file_write    pid=1042
  ```

  Только в обычном режиме: под `--quiet` в `stdout` по-прежнему не должно быть
  ничего, кроме детектов. Список односвязный, назад по нему не пройти, поэтому
  два последних события ищутся обходом всего окна от головы.

Про дубликаты: они разрешены форматом, и правило «последний выигрывает» — часть
контракта. Не отбрасывайте строку из-за них.

## Готово, когда

- Тесты списка и разбора зелёные, тесты занятия 1.1 по-прежнему зелёные.
- Прогон под санитайзером чист: пресет `asan-windows`, на Linux — `asan`.
- Разбор не падает ни на одном вырожденном входе — он либо возвращает событие,
  либо честно сообщает, что строка битая.

## Продвинутая часть

Нерекурсивное освобождение списка и объяснение, **при какой длине рекурсивная
версия уронит стек** — с экспериментом, а не с оценкой сверху.

Число будет разным на разных платформах и разных уровнях оптимизации, и это часть
ответа: попробуйте `-O0` и `-O2` и объясните разницу.

## На что смотреть

**Тесты выданы заранее, и это не подсказка, а спецификация.** Прочитайте их
до того, как писать код: они называют поведение на вырожденных входах точнее,
чем этот текст.

**`std::string` по значению.** Пока за это не снимают баллы, но с занятия 1.3
будут — ссылки появляются на лекции 3. Заготовка `l1.2` принимает параметры
указателем и по значению именно поэтому: ссылок вы ещё не проходили.

**Что случится, если между `new` и `delete` вылетит исключение.** Пока
исключений в коде нет — они на лекции 3. Вопрос вернётся на занятии 1.3, и там
вы это докажете на своём коде.
