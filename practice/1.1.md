# Занятие 1.1. Каркас и первый детект

> [Лекция 1](../lectures/01/lecture.md): типы, control flow, `std::print`, препроцессор, CE/RE/UB.

Первое занятие целиком про то, чтобы что-то работало. Ни классов, ни своих
функций — только чтение файла и печать.

## Конфигурация

```bash
cmake --preset windows -D NANO_EDR_LESSON=1.1
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Что делают эти команды, что нужно
установить и откуда их запускать — в [`project/README.md`](../project/README.md).
Ключ один — номер занятия; всё остальное берётся из него.

## На паре

1. Собрать проект и запустить заготовку на журнале:
   `./build/windows/Release/nano-edr scenarios/phishing_macro.log`, на Linux —
   `./build/linux/nano-edr scenarios/phishing_macro.log`. Своего кода
   тут ещё нет ни строки, и шаг всё равно первый: пока не видно, что сборка
   проходит и файл читается, любая ошибка дальше выглядит как ошибка
   в собственном коде.
2. Прочитать журнал событий построчно — `std::ifstream` плюс `std::getline`.
   Журнал это `scenarios/*.log`: текстовые строки вида
   `ts=число type=... pid=... key=value`. Пустые строки и комментарии
   пропустить: это не события, и детектов по ним быть не должно.
3. Посчитать события каждого типа (поле `type=`) и напечатать сводку: сколько
   событий всего и сколько каждого типа в отдельности. Формат вывода —
   свободный.
4. Найти события, содержащие подозрительный признак, и напечатать их
   как детекты в `stdout`. Список признаков и формат детекта — ниже, оба
   заданы точно.
5. Добавить опцию `--quiet`. С ней программа печатает только детекты
   и ничего больше.

**Список признаков.** Четыре подстроки, ровно в этом порядке:

```
wscript.exe
.locked
certutil.exe
\Startup\
```

Порядок важен: если в одной строке нашлось несколько признаков, детекты
печатаются в порядке этого списка — по одной строке на признак.

**Формат детекта:**

```
[DETECT] строка <номер>, признак <признак>: <строка журнала целиком>
```

- `<номер>` — номер строки в файле, начиная с единицы, считая **все** строки:
  и комментарии, и пустые.
- `<признак>` — та подстрока из списка, которая нашлась.
- `<строка журнала целиком>` — ровно то, что прочитано, без изменений
  и без обрезания.

**Что не является событием.** Строки, которые после необязательных пробелов
и табуляций начинаются с `#` или `;`, и полностью пустые строки.

## Что понадобится из библиотеки

Лекция 1 этого не проходила, а занятию оно нужно с первой минуты.

| | |
|---|---|
| `std::ifstream log(path);` | открыть файл на чтение (`<fstream>`); `if (!log)` — не открылся |
| `std::getline(log, line)` | прочитать очередную строку в `std::string`; в условии `while` — пока строки есть |
| `line.find(sub)` | позиция подстроки либо `std::string::npos`, если её нет |
| `line.substr(from, count)` | кусок строки |
| `line.size()`, `line[i]` | длина и символ по индексу |
| `std::vector<std::string>` | список строк (`<vector>`): `push_back`, `size()`, `[i]` |
| `std::print(stderr, "…{}\n", x)` | печать в поток ошибок; `stderr` — из `<cstdio>` |

## Готово, когда

- На трёх сценариях вывод совпадает с эталоном побайтово.
- Сборка чистая при `-Wall -Wextra`: пресет `strict-windows`, на Linux —
  `strict`.

## Что выдаётся

- `tasks/1.1/tests/expected/` — эталоны вывода на трёх сценариях.
- `tasks/1.1/tests/run_case.cmake` — скрипт сравнения. Подключается ключом
  `-D NANO_EDR_LESSON=1.1`, правки в вашем `CMakeLists.txt` не требует.

## Тесты

Три случая, по одному на сценарий: `scenarios/phishing_macro.log`,
`scenarios/ransomware.log`, `scenarios/clean_office.log`. Каждый запускает
вашего агента на журнале событий и сравнивает вывод детектов с эталоном.

### Запуск тестов

```bash
ctest --preset windows
```

На Linux вместо `windows` — `linux`. При расхождении тест печатает первую
разошедшуюся строку — с неё и начинайте.

### Что именно проверяется

Тесты сравнивают вывод команды

```bash
nano-edr <журнал> --quiet
```

Под `--quiet` агент печатает **только детекты, по одной строке на детект,
и ничего больше**. Сравнение побайтовое: совпадать обязано всё, включая
пробелы. Одно исключение — перевод строки: на Windows `stdout` в текстовом
режиме отдаёт `CRLF`, и скрипт сравнения это учитывает. Остальное, где формат
свободен, проверять никто не будет.

### На что обратить внимание

**Комментарии в журналах содержат ровно те слова, которые ищет агент.**
В `clean_office.log` есть строка про правило «любой `wscript.exe` — атака»,
в `ransomware.log` — комментарий с `.locked`.

**Номер строки считается по файлу, а не по событиям** — включая комментарии
и пустые. Иначе по нему нельзя открыть файл и посмотреть.

**В эталоне `clean_office` один детект, и это не ошибка эталона.** Сценарий
действительно запускает `wscript.exe` — корпоративный скрипт подключения
дисков. Признак-подстрока отличить его от фишинга не может, потому что разница
не в тексте записи, а в том, кто этот процесс породил и что было до него.
Поля появятся в части 2, связи и время — в части 3.
