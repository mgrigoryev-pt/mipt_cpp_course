# Занятие 1.1. Каркас и первый детект

> [Лекция 1](../lectures/01/lecture.md): типы, control flow, `std::print`, препроцессор, CE/RE/UB.

Первое занятие целиком про то, чтобы что-то работало. Ни классов, ни своих
функций, ни границы `os.h` — только чтение файла и печать.

## Конфигурация

```bash
cmake --preset windows -D NANO_EDR_LESSON=1.1
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Что делают эти команды, что нужно
установить и откуда их запускать — в [`project/README.md`](../project/README.md).
Ключ один — номер занятия; всё остальное берётся из него. Комплекта заготовок
на этом занятии нет: фиксировать ещё нечего, весь код лежит в `main`.

## На паре

1. Собрать проект и запустить заготовку на журнале:
   `./build/windows/Release/nano-edr scenarios/phishing_macro.log`, на Linux —
   `./build/linux/nano-edr scenarios/phishing_macro.log`. Своего кода
   тут ещё нет ни строки, и шаг всё равно первый: пока не видно, что сборка
   проходит и файл читается, любая ошибка дальше выглядит как ошибка
   в собственном коде.
2. Прочитать журнал событий построчно — `std::ifstream` плюс `std::getline`.
   Журнал это `scenarios/*.log`: текстовые строки вида
   `ts=... type=... pid=... key=value`.
3. Посчитать события каждого типа и напечатать сводку.
4. Найти строки, содержащие подозрительный признак (`wscript.exe`, `.locked`),
   и напечатать их как детекты.

Всё в `main`, без своих функций — их ещё не было. Да, получится длинно;
на занятии 1.2 проект впервые разъедется на файлы, и разницу между «всё
в одном месте» и «разложено по смыслу» будет видно глазом.

**Формат детекта задан точно, и его надо прочитать до того, как писать
печать.** Он описан в `tasks/1.1/tests/README.md` вместе со списком признаков
и правилом про порядок. Коротко:

```
[DETECT] строка <номер>, признак <признак>: <строка журнала целиком>
```

Под `--quiet` агент печатает только детекты и ничего больше. В обычном режиме
формат свободен: статистика, предупреждения и приветствия — ваше дело,
их никто не сравнивает.

## Что понадобится из библиотеки

Лекция 1 этого не проходила, а занятию оно нужно с первой минуты.

| | |
|---|---|
| `std::ifstream log(path);` | открыть файл на чтение (`<fstream>`); `if (!log)` — не открылся |
| `std::getline(log, line)` | прочитать очередную строку в `std::string`; в условии `while` — пока строки есть |
| `line.find(sub)` | позиция подстроки либо `std::string::npos`, если её нет |
| `line.substr(from, count)` | кусок строки |
| `line.size()`, `line[i]` | длина и символ по индексу |
| `std::vector<std::string>` | список строк (`<vector>`): `push_back`, `size()`, `[i]` |
| `std::print(stderr, "…{}\n", x)` | печать в поток ошибок; `stderr` — из `<cstdio>` |

## Дома

- Список признаков вместо одного — четыре подстроки в порядке из README тестов.
- Счётчик неразобранных строк и итоговое предупреждение, если они были. Строки
  с `#` или `;` и пустые — не «неразобранные»: это не события, детектов по ним
  быть не должно.
- Флаг `--quiet` в том виде, в каком его ждут тесты.
- Сборка и тесты проходят.

## Готово, когда

- На трёх сценариях вывод совпадает с эталоном побайтово.
- Сборка чистая при `-Wall -Wextra`: пресет `strict-windows`, на Linux —
  `strict`.

## Продвинутая часть

Сгенерировать нагрузочный журнал — два миллиона строк, по умолчанию
в `scenarios/stress.log`:

```bash
./tools/win-x64/gen_stress.exe      # Windows
./tools/linux-x64/gen_stress        # Linux
```

Прогнать на нём агента, замерить время через `std::chrono`
и **объяснить, куда оно ушло**.

Объяснение важнее числа. «Медленно из-за чтения файла» — это догадка; чтобы
она стала выводом, надо отдельно замерить чтение без разбора.

## Что выдаётся

- `tasks/1.1/tests/expected/` — эталоны вывода на трёх сценариях.
- `tasks/1.1/tests/run_case.cmake` — скрипт сравнения. Подключается ключом
  `-D NANO_EDR_LESSON=1.1`, правки в вашем `CMakeLists.txt` не требует.

Заготовок интерфейсов на этом занятии нет: нечего ещё фиксировать.

## На что смотреть

**Комментарии в журналах содержат ровно те слова, которые ищет агент.**
В `clean_office.log` есть строка про правило «любой `wscript.exe` — атака»,
в `ransomware.log` — комментарий с `.locked`. Агент, читающий файл как плоский
текст, доложит о них как о детектах, и тест это покажет. Комментарии и пустые
строки событиями не считаются.

**Печатать в `stdout` или в `stderr`.** Детекты — в `stdout`, их сравнивают
с эталоном. Предупреждения о битых строках — в `stderr`: они к результату
не относятся, а под `--quiet` в `stdout` не должно быть ничего, кроме детектов.

**Номер строки считается по файлу, а не по событиям** — включая комментарии
и пустые. Иначе по нему нельзя открыть файл и посмотреть.
