# Тесты занятия 2.1

Пять групп: событие с инвариантом, разбор строки, окно событий, условия-функторы
и обёртка над границей `os.h`.

## Как подключить

```bash
cmake --preset windows -D NANO_EDR_LESSON=2.1
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Правки в вашем `CMakeLists.txt` не нужны:
тесты линкуются с библиотекой `nano_edr_core`, а она собирается сама из всех
`.cpp` в `src/`, кроме `main.cpp`.

Заготовки берутся из среза **`l2.1`**, и наборы занятий 1.2 и 1.3 сюда уже
не входят: против этого среза они бы не собрались. Это не поломка, а содержание занятия: `Event` стал классом,
разбор отдаёт `EventParts` вместо `Event`, список стал классом с инвариантом.
Проверять новые типы старыми тестами нечем — тесты заменены, а не потеряны.

## Что проверяется

**Инвариант вместо проверки после создания.** Главный вопрос занятия — что
происходит, когда объект создать нельзя. Правильный ответ: исключение
из конструктора. Если у вас есть способ получить `Event`, который «создался,
но пользоваться нельзя», или `OsHandle` с методом `is_valid()`, — инварианта
нет, и половина тестов это покажет.

**Разделение «перевозчик» и «тип с инвариантом».** `EventParts` — агрегат
без обещаний: разбор строки законно не удаётся, журнал пишет чужой код.
`Event` — тип с обещаниями. Тест «разбор не проверяет, что ts число»
не придирка: один вопрос должен проверяться в одном месте, иначе две проверки
однажды разойдутся.

**Один формат в одном месте.** `operator<<`, `ToString` и `std::format` обязаны
давать одну и ту же строку. Два формата одного объекта расходятся на первой
правке, и расходятся молча.

**Условие настраивается.** Это то, чего не умеет функция: состояние живёт
в объекте. `FieldEndsWith("cmdline", ".js")` и `FieldEndsWith("cmdline", ".exe")`
— один класс, два объекта, а не две функции.

## Обязательно прогнать под санитайзером

Два случая — «тысяча элементов освобождается деструктором» и «на исправном
журнале хендл создаётся и освобождается» — под обычной сборкой не проверяют
почти ничего. Они и не должны: утечку видит не тест, а санитайзер.

```bash
cmake --preset asan -D NANO_EDR_LESSON=2.1
cmake --build --preset asan
ctest --preset asan
```

Незакрытый `os_handle*` — утечка, и именно так она и обнаруживается.

## Ловушка, про которую стоит знать заранее

**Пустое тело деструктора списка не даёт утечки.** Убрав тело `~EventList`,
легко решить, что список теперь течёт. Не течёт: поле `head_` — `unique_ptr`,
и оно разрушится само. Меняется не наличие освобождения, а способ: вместо
цикла цепочку разберёт **рекурсия** неявных деструкторов. Тесты идут
до тысячи узлов, и рекурсия их выдержит. На десятках тысяч — не выдержит.

То есть зелёный прогон и чистый санитайзер здесь не доказывают, что деструктор
написан правильно. Смотреть надо в код.

## Чего тесты не проверяют, но спросят на паре

**Трамплин.** Граница `os.h` принимает указатель на функцию и `void*`. Метод
класса указателем на функцию не является: у него есть неявный `this`. Поэтому
подписываются статическим методом, а объект передают через `void*`.

Трамплин обязан быть `noexcept` и обязан ловить внутри всё: раскрутка стека
через кадры C — неопределённое поведение. Тестом это не поймать (в отладочной
сборке симулятор заметит и завершит программу, но полагаться на чужую проверку
вместо своей — плохая привычка), а на паре спросят обязательно.

**Почему хендл нельзя копировать.** `os_handle*` — владеющий ресурс, за которым
стоит открытый файл, поток и отчёт. Две обёртки над одним указателем позвали бы
`os_free` дважды. Проверка на копируемость в тестах есть, а вот объяснить,
почему запрет дешевле, чем придуманная семантика копии, придётся словами.
