# Тесты занятия 1.1

Три случая, по одному на сценарий: `phishing_macro`, `ransomware`,
`clean_office`. Каждый запускает вашего агента на журнале событий и сравнивает
вывод детектов с эталоном побайтово.

## Как подключить

Тесты появляются при конфигурации, отдельной правки `CMakeLists.txt`
не требуется:

```bash
cmake --preset windows -D NANO_EDR_LESSON=1.1
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Тесты запускают цель `nano-edr`; если
ваша называется иначе, задайте имя через `NANO_EDR_AGENT`.

При расхождении тест печатает первую разошедшуюся строку — с неё и начинайте.

## Что именно проверяется

Тесты сравнивают вывод команды

```
nano-edr <журнал> --quiet
```

Под `--quiet` агент печатает **только детекты, по одной строке на детект,
и ничего больше**. Статистика, предупреждения, приветствия — всё это в обычном
режиме, где формат свободен и проверять его никто не будет.

Строка детекта:

```
[DETECT] строка <номер>, признак <признак>: <строка журнала целиком>
```

- `<номер>` — номер строки в файле, начиная с единицы, считая **все** строки:
  и комментарии, и пустые.
- `<признак>` — та подстрока из списка ниже, которая нашлась.
- `<строка журнала целиком>` — ровно то, что прочитано, без изменений
  и без обрезания.

Сравнение побайтовое. Перевод строки нормализуется: на Windows `stdout`
в текстовом режиме отдаёт `CRLF`, и скрипт прогона это учитывает. Всё
остальное — включая пробелы — обязано совпадать.

## Список признаков

Четыре подстроки, ровно в этом порядке:

```
wscript.exe
.locked
certutil.exe
\Startup\
```

Порядок важен: если в одной строке нашлось несколько признаков, детекты
печатаются в порядке этого списка — по одной строке на признак.

## Что не является событием

Строки, которые начинаются (после необязательных пробелов и табуляций)
с `#` или `;`, и полностью пустые строки. Детектов по ним быть не должно —
в журналах курса комментарии содержат ровно те слова, которые ищет агент.

## Про `clean_office`

Эталон чистого сценария содержит **один детект**, и это не ошибка эталона:
`clean_office` действительно запускает `wscript.exe` — корпоративный скрипт
подключения дисков. Признак-подстрока отличить его от фишинга не может,
потому что разница не в тексте записи, а в том, кто этот процесс породил
и что было до него. Поля появятся в части 2, связи и время — в части 3.
