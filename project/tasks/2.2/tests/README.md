# Тесты занятия 2.2

Только то, что добавилось: `Condition` и классы правил `RuleBase` / `MatchRule`.

**Тесты занятия 2.1 остаются подключёнными и обязаны проходить.** Событие,
разбор, окно, обёртка над границей и четыре условия-функтора не изменились —
их заголовки в срезе `l2.2` те же самые. Если что-то из них сломалось, значит
сломалось при переделке правил, и узнать об этом лучше сразу.

## Как подключить

```bash
cmake --preset windows -D NANO_EDR_LESSON=2.2
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Правки в вашем `CMakeLists.txt` не нужны:
тесты линкуются с библиотекой `nano_edr_core`, а она собирается сама из всех
`.cpp` в `src/`, кроме `main.cpp`.

Набор занятия 2.1 приходит вместе с этим — почему, сказано выше.

## Зачем понадобился пятый класс условия

На занятии 2.1 условий было четыре — четыре класса с `operator()`. Положить
их в один вектор нельзя: вектор хранит объекты одного типа, а объединить
четыре в один способ к этому занятию не пройден.

А вектор условий нужен: правило — это «все условия выполнены».

Отсюда `Condition`: один класс, внутри переключатель вида сравнения. Решение
временное и заявляется таковым. На занятии 2.3 `virtual` уберёт `switch`,
и четыре класса вернутся — но уже наследниками общего интерфейса, и хранить
их можно будет указателями.

## Главный вопрос занятия

**Почему `MatchRule` нельзя хранить в `std::vector<RuleBase>`?**

Тест `sizeof(MatchRule) > sizeof(RuleBase)` — половина ответа. Вторая половина
словами: вектор хранит объекты по значению, и при копировании `MatchRule`
в ячейку размера `RuleBase` от него осталась бы только базовая часть. Вектор
условий исчез бы, `Check` вызывать было бы не у чего.

Это называется **срезкой**, и компилятор про неё молчит: копирование
наследника в базу совершенно законно. Пока `Check` невиртуальный, обойти
это нечем — хранить приходится вектором конкретного типа.

На 2.3 появится `virtual`, и правила будут храниться указателями на базу.
Срезки не будет, потому что указатель одного размера всегда.

## Пустые случаи проверяются отдельно

Условие с пустым списком значений и правило без условий решены по-разному,
и почему — сказано в постановке занятия (`practice/2.2.md`). Здесь важно
другое: оба случая в тестах есть, и пройти их «как получится» не выйдет.
